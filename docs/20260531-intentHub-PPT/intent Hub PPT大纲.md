# PPT大纲

**整体基调**

这套 PPT 不走技术汇报风，而是做成一本“AI 产品白皮书 / 产品杂志”。整体感觉要专业、有叙事、有产品质感，适合项目介绍、路演、阶段汇报或对外展示。

视觉关键词：
- 深靛蓝、瓷白、墨黑、银灰
- 大标题、宽留白、产品化图示
- 能力地图、流程图、界面截图、场景页
- 少量细腻背景纹理，不做强科技光效
- 像“深度产品介绍文章”而不是“工程架构说明”

推荐主色：
- 深靛蓝：`#0A1F3D`
- 瓷白：`#F1F3F5`
- 浅灰蓝：`#E4E8EC`
- 墨黑：`#0A0A0B`
- 银灰：`#9AA4B2`

推荐页数：15 页  
推荐时长：15-20 分钟  
叙事主线：问题出现 → 产品定位 → 核心能力 → 使用路径 → 应用场景 → 产品价值 → 未来方向

---

## 1. 封面：Intent Hub

**页面基调：产品发布 / 高级开场**

**标题：** Intent Hub  
**副标题：** 让 AI 能力找到正确入口

**页面内容：**
- Intent Hub 是一个面向 AI 应用和 Agent 工作流的意图路由平台。
- 它帮助系统理解用户输入，并判断应该调用哪个能力、Skill 或 Agent。
- 这份介绍将重点说明它的产品定位、核心能力和典型应用。

**讲述重点：**
开场不讲技术，直接建立产品认知：Intent Hub 是“AI 能力选择层”。

**设计样式：**
- 深靛蓝满版背景。
- 中央偏左放超大标题 `Intent Hub`。
- 副标题使用瓷白色，字号明显小一档。
- 右侧可以放一个抽象视觉：用户输入像一束信号进入中心节点，再分散到多个能力节点。
- 页面底部放一行小字：`Intent · Route · Skill · Agent`
- 整体像产品杂志封面，克制、有留白。

## 2. 背景：AI 能力变多之后，入口开始失控

**页面基调：问题洞察 / 产品叙事起点**

**标题：** 能力越多，选择越难

**页面内容：**
今天的 AI 系统往往不再只有一个模型，而是接入了越来越多能力：

- 文档处理
- 网页浏览
- 知识库整理
- 代码任务
- 数据分析
- 内容生成
- 自动化工作流
- 专用 Agent 或 Skill

但用户真正想做的事情很简单：  
他们只想说出任务，而不是先判断应该打开哪个工具。

**核心观点：**
AI 产品的复杂度正在从“模型能力”转移到“能力选择”。

**设计样式：**
- 瓷白背景。
- 左侧大标题，右侧放一组散落的能力卡片。
- 能力卡片用浅灰蓝底，像杂志里的信息贴片。
- 中间放一条用户输入：“帮我整理这批资料并生成结构化文档”
- 输入后方分叉到多个能力卡片，表现“选择困难”。
- 页面下方用深靛蓝强调一句：`The new problem is routing.`

## 3. 产品定位：Intent Hub 是 AI 能力的路由中枢

**页面基调：定义产品 / 建立主概念**

**标题：** 一个统一的意图路由中枢

**页面内容：**
Intent Hub 的核心作用可以概括为三步：

1. 接收意图  
用户或 Agent 提交自然语言任务。

2. 判断方向  
系统根据已有能力描述、路由配置和索引，判断最匹配的能力。

3. 返回建议  
输出 route key、匹配结果或 dispatch 建议，让上层系统继续执行。

**一句话定位：**
Intent Hub 不直接替代 Agent，而是帮助 Agent 找到正确的能力入口。

**设计样式：**
- 使用横向三段式图示：`User Intent` → `Intent Hub` → `Capability`
- 中间 Intent Hub 用深靛蓝实心模块。
- 左右两侧用瓷白或浅灰蓝模块。
- 背景可加入非常淡的纸张纹理。
- 标题采用杂志式大标题，正文保持短句。

---

## 4. 产品价值：把“能力选择”产品化

**页面基调：价值提炼 / 面向决策者**

**标题：** 从隐藏逻辑，到可管理能力

**页面内容：**
没有 Intent Hub 时，能力选择通常散落在：

- prompt 里
- 代码判断里
- 人工说明里
- 每个 Agent 自己的逻辑里
- 用户记忆里

Intent Hub 把这件事抽出来，变成一个独立、可管理、可测试、可优化的产品能力。

**四个价值点：**
- 统一入口：用户只表达任务，不需要知道工具名。
- 能力沉淀：Skill 可以被扫描、导入和维护。
- 可测试：输入是否命中预期能力可以被验证。
- 可优化：路由质量可以被诊断和持续调整。

**设计样式：**
- 使用杂志式左右分栏。
- 左侧放一句大号论断：“能力选择需要产品化。”
- 右侧四个价值模块纵向排列。
- 每个模块有短标题和一句说明。
- 深靛蓝用于标题和关键数字，浅灰蓝用于模块背景。

## 5. 产品总览：Intent Hub 的能力地图

**页面基调：全局视图 / 产品能力地图**

**标题：** 一张图看懂 Intent Hub

**页面内容：**
Intent Hub 可以分为五类核心能力：

1. 意图路由  
把自然语言输入匹配到合适能力。

2. Skill 管理  
扫描、导入、维护本地或团队 Skills。

3. 路由测试  
验证某条输入会命中哪个能力。

4. 诊断优化  
发现重叠、误命中、索引问题。

5. 集成接入  
通过 Web、CLI、SDK 进入不同使用场景。

**讲述重点：**
这页是后续内容的目录页。听众看完后应该知道产品不是单点功能，而是一套围绕“能力路由”的完整工作台。

**设计样式：**
- 中心放 Intent Hub 圆形或方形主节点。
- 周围放五个能力模块，形成“能力星图”。
- 使用深靛蓝主节点，浅灰蓝能力模块。
- 背景可使用淡淡的等高线或纸面纹理。
- 每个模块配一个极简图标，但不要过度装饰。

## 6. 核心能力一：意图路由

**页面基调：核心能力展开 / 清晰有力**

**标题：** 把自然语言变成能力方向

**页面内容：**
用户输入通常不是结构化命令，而是自然语言：

- “帮我整理 wiki”
- “测试一下这个网页”
- “把这篇文章改得不像 AI 写的”
- “根据这些资料生成项目介绍”
- “分析这个功能应该走哪个工具”

Intent Hub 接收这些输入后，返回最可能的 route 或 dispatch 建议。

**产品价值：**
- 降低用户选择工具的成本。
- 减少 Agent 自己判断能力的复杂度。
- 让能力调用有统一入口和可追踪结果。

**设计样式：**
- 左侧放 4-5 条自然语言输入，像杂志中的引用条。
- 中间用深靛蓝模块表示 Intent Hub。
- 右侧输出结构化结果，例如：
  - `wiki-builder`
  - `browser-test`
  - `writing-cleanup`
  - `ppt-generator`
- 背景保持瓷白。
- 输出区域可以做成“产品结果卡片”。

## 7. 核心能力二：Skill 扫描与导入

**页面基调：产品流程 / 能力进入系统**

**标题：** 让分散的 Skill 进入统一目录

**页面内容：**
很多团队已经有自己的 Skill、脚本或 Agent 能力，但它们通常分散在本地目录或项目仓库里。

Intent Hub 支持通过 Web 或 CLI 扫描 Skill：

1. 选择本地 Skill 目录。
2. 读取目录中的 `SKILL.md`。
3. 上传能力描述。
4. 生成或更新路由实体。
5. 同步索引后参与匹配。

**产品价值：**
- 不需要手动复制能力说明。
- 已有 Skill 可以快速进入系统。
- 团队能力可以持续更新和沉淀。

**设计样式：**
- 使用横向流程图。
- 每一步用“杂志编号 + 简短标题 + 一句说明”。
- `SKILL.md` 用文件视觉表示。
- 最后一步“可被路由”使用深靛蓝高亮。
- 页面右下角放一句：`From local skills to routable capabilities.`

---

## 8. 核心能力三：Web 管理台

**页面基调：产品界面 / 可运营**

**标题：** 路由能力需要被看见、被管理

**页面内容：**
Intent Hub 不只是一个后台接口，也提供 Web 管理台，让路由能力变成可运营的产品对象。

管理台可以支持：

- 查看和维护能力路由。
- 测试输入命中结果。
- 管理 Skill 来源。
- 处理导入草稿。
- 查看诊断结果。
- 调整配置并同步索引。

**产品价值：**
让产品、运营和开发可以在同一个界面上协作维护 AI 能力，而不是把所有逻辑藏在代码里。

**设计样式：**
- 如果有产品截图，右侧放一张大截图。
- 如果没有截图，用抽象后台 UI 线框：左侧导航、中央列表、右侧详情。
- 左侧用杂志式大标题和说明文字。
- 截图容器保持直角，轻微浅灰蓝背景，不加浓重阴影。
- 页面下方用三个标签：`Manage` / `Test` / `Improve`

## 9. 核心能力四：CLI / SDK 接入

**页面基调：开发者入口 / 产品化但不技术化**

**标题：** 进入开发者工作流

**页面内容：**
Intent Hub 不只适合在网页中使用，也可以通过 CLI 和 Python SDK 接入自动化流程。

典型动作：

- 登录远程服务。
- 查询当前身份。
- 测试一条输入的路由结果。
- 扫描本地 Skill。
- 同步路由索引。

示例：
```bash
intent-hub route "帮我整理 wiki"
intent-hub skills scan --source-path ./skills
intent-hub sync
```

**产品价值：**
Web 管理台适合运营和配置，CLI/SDK 适合开发者、自动化脚本和 Agent Runtime 集成。

**设计样式：**
- 深靛蓝背景，终端代码块使用瓷白或浅灰蓝。
- 左侧是大标题和产品说明。
- 右侧是 3 行命令，不放过多参数。
- 命令中的 `route`、`scan`、`sync` 用浅蓝或银灰突出。
- 整体像产品杂志里的“开发者页”。

## 10. 核心能力五：诊断与优化

**页面基调：质量闭环 / 可信赖**

**标题：** 路由需要持续优化

**页面内容：**
意图路由不是一次配置后永远正确。随着能力增加，系统会遇到：

- 多个能力描述相似。
- 用户表达和样本不一致。
- 新增 Skill 后没有及时同步。
- 某些 route 容易误命中。
- 能力之间边界不清楚。

Intent Hub 提供诊断和优化能力，帮助团队发现问题、修复问题、重新同步索引。

**产品价值：**
它不只是“能路由”，还帮助团队维护路由质量。

**设计样式：**
- 使用闭环图：
  `Test` → `Diagnose` → `Repair` → `Sync` → `Route`
- 中间放一句：`Routing quality is an operating loop.`
- 背景使用瓷白。
- 闭环中的 `Diagnose` 节点用深靛蓝突出。
- 页面底部用小字解释每个环节。

## 11. 使用路径：一次完整的产品体验

**页面基调：端到端流程 / 产品旅程**

**标题：** 从能力导入到路由命中

**页面内容：**
一条典型使用路径：

1. 团队准备一组 Skills。
2. 通过 Web 或 CLI 扫描 Skill。
3. Intent Hub 生成或更新路由。
4. 执行索引同步。
5. 用户提交自然语言任务。
6. Intent Hub 返回匹配能力。
7. Agent 或上层应用继续执行。

**讲述重点：**
这页把前面分散的能力串起来，让听众形成完整产品体验。

**设计样式：**
- 使用横向长流程，像杂志中的信息图。
- 每一步一个编号节点。
- 上半部分展示“能力进入系统”，下半部分展示“用户请求命中能力”。
- 用深靛蓝连线贯穿全页。
- 关键节点 `Scan`、`Route`、`Dispatch` 使用重点色。

## 12. 应用场景一：团队 Skill 能力库

**页面基调：场景化 / 团队协作**

**标题：** 场景一：团队共享 Skill 能力库

**场景描述：**
一个团队可能已经沉淀了很多 Skills：

- 文档整理
- 知识库构建
- 网页分析
- 代码审查
- 内容改写
- PPT 生成
- 数据处理

过去，用户需要知道每个 Skill 的名字、用途和触发方式。  
使用 Intent Hub 后，团队只需要把这些 Skills 纳入系统，用户通过自然语言表达任务即可。

**场景价值：**
- 降低团队内部使用门槛。
- 减少“只有作者知道怎么用”的问题。
- 让能力从个人经验变成团队资产。

**设计样式：**
- 左侧 Before：一堆分散 Skill 卡片。
- 右侧 After：统一进入 Intent Hub，再路由到正确 Skill。
- 使用对比式页面。
- Before 用灰色、分散布局。
- After 用深靛蓝主线、整齐布局。
- 页面底部放一句：`From scattered skills to shared capability.`

---

## 13. 应用场景二：Agent 产品的前置路由层

**页面基调：解决方案 / 产品架构但不技术化**

**标题：** 场景二：给 Agent 加一层能力判断

**场景描述：**
在 Agent 产品中，用户输入可能对应完全不同的处理链路：

- 查询资料
- 浏览网页
- 处理文档
- 修改代码
- 调用内部工具
- 生成内容
- 执行自动化流程

如果这些判断全部写在 Agent prompt 或业务代码里，系统会越来越难维护。

Intent Hub 可以放在 Agent Runtime 前面，先判断任务方向，再把建议交给 Agent 继续执行。

**场景价值：**
- 简化 Agent 的前置判断。
- 让能力新增和调整更独立。
- 让路由结果可以测试和诊断。

**设计样式：**
- 使用一条清晰链路：
  `User Input` → `Intent Hub` → `Dispatch Suggestion` → `Agent Runtime`
- 背景用浅灰蓝。
- Intent Hub 使用深靛蓝大模块。
- 下方用 4 个小模块表示不同执行链路。
- 版式像产品解决方案图，而不是系统架构图。

## 14. 应用场景三：AI 平台的能力运营后台

**页面基调：平台化 / 管理视角**

**标题：** 场景三：把 AI 能力变成可运营资产

**场景描述：**
当一个平台中接入的 AI 能力越来越多，真正重要的不只是“有多少能力”，还包括：

- 哪些能力已经上线？
- 哪些能力可以被路由命中？
- 哪些能力命中不稳定？
- 哪些能力描述需要更新？
- 哪些能力之间存在重叠？
- 哪些能力长期没有被使用？

Intent Hub 可以作为 AI 能力运营后台的一部分，帮助团队管理能力生命周期。

**场景价值：**
让 AI 平台从“工具集合”升级为“能力体系”。

**设计样式：**
- 使用产品看板式布局。
- 中间放一个“能力资产面板”。
- 面板内包含：
  - Skills
  - Routes
  - Drafts
  - Diagnostics
  - Sync Status
- 右侧放一段产品说明。
- 深靛蓝用于面板标题和状态高亮。
- 整页像 SaaS 产品介绍中的 dashboard 页面。

## 15. 总结：Intent Hub 的核心价值

**页面基调：价值收束 / 有记忆点**

**标题：** 让 AI 能力可发现、可路由、可运营

**页面内容：**
Intent Hub 的价值可以归纳为三句话：

1. 对用户  
不用记工具名，只需要表达任务。

2. 对 Agent  
不用写死复杂判断，可以获得统一路由建议。

3. 对团队  
能力可以被扫描、测试、诊断和持续优化。

**最终定位：**
Intent Hub 是 AI 应用中的能力选择层。

**设计样式：**
- 深靛蓝背景。
- 三句话用瓷白大字分三行展示。
- 每行关键词高亮：用户、Agent、团队。
- 页面右下角放最终定位：`Capability Routing Layer`
- 不放过多信息，让最后一页有停顿和记忆点。

---

**整套页面节奏**

- 1：封面，建立品牌感
- 2：问题，说明为什么需要它
- 3：定位，定义 Intent Hub
- 4：价值，把能力选择产品化
- 5：总览，展示能力地图
- 6-10：核心能力展开
- 11：完整使用路径
- 12-14：应用场景
- 15：总结收束

**视觉执行原则**

- 每页只讲一个核心观点。
- 标题要像杂志标题，短、有判断力。
- 正文尽量短句，不堆技术解释。
- 图示优先于代码，流程优先于接口。
- 技术名词只在需要证明产品可落地时出现。
- 深靛蓝用于封面、关键模块和总结页，不要每页铺满。
- 瓷白背景页负责承载信息，深色页负责制造节奏。
