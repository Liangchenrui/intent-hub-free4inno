## 调用方式

登录管理页面，在设置中填写 Route API Key 并保存。管理登录使用当前代码中的 `admin / 123456`，与路由密钥独立。以下为 Bash/curl 格式，密钥使用占位符：

```bash
curl --request POST 'http://127.0.0.1:5000/route' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer <保存的 Route API Key>' \
  --data-raw '{"query":"其他学校的同学怎么进学校"}'

curl --request POST 'http://127.0.0.1:5000/compat/master/predict' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer <保存的 Route API Key>' \
  --data-raw '{"text":"其他学校的同学怎么进学校","learn_from_fallback":true}'
```

`/route` 与 `/compat/bupt/route` 使用 `query`，返回 `success/data/error` 包装；`/compat/master/predict` 使用 `text`，返回结果数组。省略 `learn_from_fallback` 默认开启，BUPT 不暴露该开关。路由返回成功不等于自动语料或索引已成功写入；通过路由详情、同步状态和 `fallback_learning` 事件核对。

统一密钥为空时恢复环境 `PREDICT_AUTH_KEY` / `AUTH_CODE` 原有逻辑；BUPT 管理始终用 `AUTH_CODE`。不要把管理密码当作路由密钥。运行时设置和真实密钥不随本次提交推送。
