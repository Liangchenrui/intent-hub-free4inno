# 路由时延优化

## 目标与边界（2026-09-19，实现前记录）

用户要求按 ai-native-dev 流程完成日志分析的前四项建议。基线为请求
`f51645dd51b6464c9336b47183280c18`，输入“我要出国参加学术会议”，总耗时
30000.682 ms：准备 15738.107、向量化 3224.491、负例 1882.209、正例
1938.455、描述检索 2096.379、LLM 初始化 3566.948、LLM 调用 1474.081 ms。
来源为本地 logs.sqlite3 的路由记录及关联运行日志，非统计基准。

包括组件预热、LLM 连接复用、正负例并行、Embedding 连接复用和远程耗时证据。
不调整阈值、模型、提示词、正负例或生产部署。不假设当前约 2 秒的检索都是数据库计算。

## 设计与验收

- 启动和组件配置变更后后台预热；进程存活与路由就绪分开。预热期间预测快速返回
  503，管理接口仍可用；预热失败可通过后续就绪检查触发重试，不把初始化塞进预测。
- 每代配置独立组件、互斥初始化；配置切换不等待旧初始化，也不将旧组件发布为新配置。
  已开始的请求使用同一代组件快照。集合/索引准备仅发生在预热或同步初始化。
- LLM 使用进程内专属长生命周期事件循环，客户端按配置复用，超时仍取消调用；
  配置更新后新调用使用新客户端，旧调用结束再释放旧客户端。不得跨事件循环复用。
- 正负例并行检索，全部完成后统一过滤；负例排除、阈值、兜底和最终实体复核不变。
  子线程继承请求上下文；日志保留重叠区间，“其他耗时”按区间并集计算。
- Embedding 使用连接池；只缓存有限数量查询向量（按实例/模型配置隔离），
  避免同步大批量向量常驻。外部调用记录端到端耗时，服务端提供 timing 时单独记录，
  缺失时明确未知，不把差值直接命名为网络耗时。
- 以并发屏障、失败/取消、配置切换、真实本地 HTTP 连接复用测试验证机制；运行后端
  回归与前端构建；本地真实服务重复调用同一输入，区分冷初始化、首次预测和热缓存。

## 实施顺序与恢复

先建立组件生命周期与 LLM 运行时，再并行检索、连接池和日志显示，最后回归及真实请求。
保留已有未提交修改和 settings.json；不提交、不推送。恢复时只撤回本次对应代码差异并
重启本地服务，不回退路由数据或索引。

## 根据实测调整（2026-09-19）

预热/复用/并行完成后的三次请求为 8.51、5.32、5.06 秒，Qdrant 服务端仅 2–5 ms。
同一只读集合查询经系统代理约 1418 ms（Connection: close），直连约 155 ms
（Connection: keep-alive）。据此增加 `SERVICE_HTTP_TRUST_ENV` 布尔项，默认 true 保持
其他环境兼容；本地改为 false 只影响 Embedding/Qdrant，LLM 和系统全局代理不变。
关闭时仍执行 HTTPS 证书验证，但不继承环境代理/证书路径；依赖这些环境配置的部署应保持 true。
字段有严格类型校验，变更触发后台预热，并在设置页提供开关。

### 真实服务结果

2026-09-19，Windows 本地 Flask、同一配置的 Embedding/Qdrant 和 deepseek-flash，
请求内容完全相同。先对仍运行的旧服务测三次，再重启新实现并测三次；代理开关是最后
一组明确变更的网络变量。服务端耗时如下：

| 状态 | 第一次 | 第二次 | 第三次 | 样本中位数 |
| --- | ---: | ---: | ---: | ---: |
| 旧实现，组件已热 | 10.251 s | 11.047 s | 12.059 s | 11.047 s |
| 预热/复用/并行，仍经代理 | 8.515 s | 5.316 s | 5.063 s | 5.316 s |
| 全部优化，内部服务直连 | 2.591 s | 1.704 s | 1.570 s | 1.704 s |

最终组第一次查询缓存未命中，后两次命中；三次均复用 LLM 客户端。中位数下降
84.57%，是这组小样本与缓存条件下的观察值，不是生产 p50/p95 承诺。
全部九次请求均通过原 LLM 兜底命中路由 103，分数与阈值未改变。
随后两个并发请求也均命中 103（1.998 s、1.949 s），且请求 ID/阶段记录彼此独立。

最终组首次 Embedding 调用 220.221 ms；Qdrant 三次查询 299.193、296.392、180.573 ms，
对应服务端处理约 2.6–3.5 ms。末次总耗时 1570.429 ms，LLM 调用 1245.773 ms，
剩余主要耗时已转为实际模型响应。此实现不改变基础设施部署位置。

启动预热从用户请求路径移到后台：最终组启动预热 6617.124 ms，预测准备仅 0.7–1.0 ms。

### 限制与恢复

旧组件代为避免打断同步或在途调用，保留到进程退出统一关闭；频繁切换配置后可重启回收。
外部模型时延仍有波动；没有执行生产压测或大规模效果评估。Embedding 服务端处理时间
当前未提供可可靠使用的字段，因此只记录客户端耗时；不推断模型推理或网络的占比。

需要恢复代理时，在设置页开启“内部服务继承系统代理与证书环境”，保存后等待后台预热；
LLM 与系统全局代理从未更改。撤回代码时仅撤回本次优化差异并重启服务，保留路由数据、
本地密钥和其他已有修改。
