# Intent Hub × Jev 思想结合：动态能力集合下的可靠语义路由研究

调研日期：2026-09-17。研究对象是方法思想的结合，不调用 Jev API，不假定掌握 Jev 的训练方法。本报告区分已发表工作、预印本、项目事实和待验证研究设想；未运行模型实验，文中的预算、规模和改进目标均为建议值。

## 1. 结论与选题建议

**值得做，但应把创新重点从“增加适用性判断和拒答”收紧到“能力目录变化后，如何以较少标注和计算恢复可靠路由”。**

Intent Hub 提供可变能力目录、正负例、生命周期和实际路由链路；Jev 的启发是将语言理解变成有明确判定标准、有限输出和不确定性信号的决策。二者结合适合研究一种独立于具体模型的能力决策机制。没有必要复刻 Jev，也没有证据表明复刻其接口就能复现其模型能力。

建议主选题：

> **面向动态能力目录的轻量选择性路由：适用性判别与变更后风险再校准**  
> Lightweight Selective Routing over Evolving Capability Catalogs: Applicability Estimation and Post-Change Risk Recalibration

第一阶段优先回答一个可以被证伪的问题：

> 当新增相邻能力、删除现有能力或修改能力职责时，相比固定相似度阈值和普通重排器，能否在相同误路由约束下，用更少的新标注恢复自动路由覆盖率？

用户提出的“面向动态能力集合的轻量语义路由：适用性判别与选择性拒答”适合作为总方向，但作为论文题目仍较宽。**“动态”必须进入训练划分、实验干预和主要指标，不能只意味着系统支持新增路由。**

| 路线 | 建议优先级 | 可以争取的贡献 | 主要风险 |
|---|---|---|---|
| A. 目录变化后的低成本再校准 | 主线 | 明确变化协议、标注预算下的风险—覆盖率恢复方法 | 动态环境的保证容易说过头 |
| B. 区分检索遗漏与真实不适用 | 主线的一个模块或第二篇 | 预算受限的扩召回决策、减少错误拒答 | 只加一次 Top-K 扩容创新不足 |
| C. 能力边界反事实评测与学习 | 最适合先落地 | 相同请求在不同契约下的标签变化、可复现动态基准 | 仅有合成数据或模板线索会削弱价值 |
| D. 等价能力感知的稳定路由 | 有价值的扩展 | 避免把“都可完成”误当歧义，减少无意义拒答 | 等价工具标注已有直接工作 |
| E. 澄清、拒答、升级的价值决策 | 后续 | 比较询问用户、扩大检索、交给大模型的收益与成本 | 用户反馈与交互实验成本较高 |

建议采用 **A 为论文问题、C 为评测基础、B 为一个受控模块** 的组合。不要同时把增量训练、完整规划、多工具执行、强化学习和在线用户实验都纳入第一篇。

## 4. 将问题定义准确，才能避免做成普通分类

### 4.1 动态能力不是动态候选列表的同义词

令请求与必要上下文为 `x`，时间 `t` 的注册能力目录为 `C_t`。每项能力 `c` 有版本化契约 `d_c`，包含做什么、不做什么、输入要求及可由程序核验的前置条件。

定义：

- `Y(x,C_t)`：当前目录中能独立满足请求的所有有效能力，可为空、单个或多个。
- `R_k(x,C_t)`：检索器返回的候选集合。
- `f(x,C_t)`：最终选择的能力。
- `g(x,C_t) ∈ {0,1}`：是否接受并自动路由。

“动态”至少包含四种不同干预：新增能力、删除/停用能力、修改已有能力职责、加入等价或高度相邻能力。还应区分用户请求分布变化与目录本身变化，第一篇优先固定请求分布、只操作目录。

例子：用户始终说“把这份报告转换为 PDF”。

| 目录状态 | 正确结果 |
|---|---|
| 只有 PDF 阅读能力 | `no_match` |
| 新增支持该输入格式的转换能力 | 路由到转换能力 |
| 转换能力修改为只支持图片，请求输入是 DOCX | `no_match` 或交给外部系统 |
| 有两个满足约束的等价转换能力 | 二者均可接受，按明确成本策略选择 |
| 转换能力存在但未被召回 | 内部检索错误，应考虑扩召回，不能据此宣称全目录无能力 |

这类“请求不变、目录变、答案可能变”的样本，比随机替换一个标签更能说明研究价值。

### 4.2 必须分开的状态

| 状态 | 定义 | 合理动作 |
|---|---|---|
| 真实不适用 | 当前目录无能力满足请求 | `no_match` / 外部升级 |
| 检索遗漏 | 存在适用能力，但未进入候选集 | 扩召回或切换检索方法 |
| 信息不足 | 缺少信息，导致适用能力无法确定 | 澄清 |
| 多个等价能力 | 任一能力均满足要求 | 依据成本、权限等固定策略择一 |
| 真正歧义 | 不同解释对应不同目标，选择取决于用户意图 | 澄清 |
| 复合请求 | 没有单项能力可独立完成，但可能联合完成 | 移交编排；首篇不承担完整规划 |
| 条件不满足 | 语义上适用，但登录、资源或权限状态不满足 | 返回阻塞原因；不让模型臆测事实 |

同一个请求可能同时缺少资源和语义信息。数据中保留多个原因标签，策略执行时再规定优先级，不强迫标注员把所有现象压成互斥类别。

还须区分“路由到负责收集参数的能力”和“立即执行工具”。如果该能力本来负责追问文件位置，那么缺少文件位置未必阻止路由；只有缺少信息会改变该选谁，才属于本研究的路由澄清。能力契约必须明确这个边界。

### 4.3 主要优化目标

自动路由覆盖率：

`Coverage = P(g=1)`

接受样本上的误路由风险：

`Risk_sel = P(f(x,C_t) ∉ Y(x,C_t) | g=1)`

研究目标是：在 `Risk_sel ≤ α`、推理成本与更新标注预算受限时，提高 Coverage。若没有接受样本，风险记为 N/A，不用“0% 错误”掩盖全部拒答。

同时报告 `P(g=1 | Y=∅)`，即真实库外请求的误接受率。它与 `Risk_sel` 的分母不同，不能互相替代。测试集 OOS 比例改变会影响总体风险，因此除了固定混合比例，还要分层报告并做比例敏感性分析。

## 5. 五个可执行方向及其创新边界

### A. 目录变化后的低成本再校准：最建议作为主线

**假设 H1：** 将独立的请求—能力适用性分数，与依赖候选集合的接受策略分离，可减少无关能力加入带来的分数扰动；结合目录变化类型，有机会用更少标注恢复可接受风险。

方法起点：用一个共享小模型计算 `a(x,d_c)`；检索与排序选出能力；另用最高适用性、竞争者、契约冲突与目录变更信号估计最终选择是否可接受。每次目录变更后，比较冻结阈值、全量再校准、固定预算随机再校准、冲突邻域再校准。

为什么有空间：固定训练类别的 OOS 分类与固定候选选择，不能直接回答“注册一个新能力要标多少数据，才能恢复原有可靠性”。这是 Intent Hub 的管理场景能提供的实际问题。

关键限制：`a(x,d_c)` 独立于其他候选，只表示其数值不会因 softmax 分母变化；加入新能力仍会改变胜者、最大值分布和错误率。因此不能把独立打分称为“目录变化下天然校准”。

可发表贡献应包含：变更协议、一个明确超越简单滚动校准的机制、多个目录/能力族上的标注效率结果。若只显示固定阈值失效，属于有用诊断，但算法贡献仍弱。

**停止条件：** 在相同新标注预算下，邻域策略不优于随机再校准，或收益全部来自额外样本，则放弃“更省标注”的方法主张，转为评测研究。

### B. 召回失败感知的选择性路由：解决容易被忽略的错误拒答

**假设 H2：** 不把“Top-K 均不适用”直接视为全目录无匹配，而是判断是否值得扩大检索，可以改善预算约束下的正确路由覆盖率。

最小实现：初始 K 取 5 或 10；低适用性时选择扩大至 20/50、加入词法检索，或拒答。升级触发器可使用检索分布、召回器分歧、目录规模、候选适用性分布；不要声称能直接观察遗漏的正确答案。

需要比较：固定 K、大 K、随机扩容、简单分数触发、学习触发。还需使用“把一个有效能力补入候选”的诊断实验，将检索上限与判别能力分开。

创新不能只是增加 K。更有价值的是学习“额外计算的预期收益”，在相同平均成本及尾延迟限制下胜过固定大 K。若目录很小、全量判别已足够快，本方向的实用价值会明显下降。

### C. 能力边界反事实评测与对比学习：最适合立即动手

**假设 H3：** 模型训练时看到同主题但动作、限制不同的边界对，比增加普通同义改写更有利于未见能力上的适用性判断。

构造两类成对数据：

1. 请求不变，仅改变能力契约，例如“起草但不发送”变成“起草且可发送”。
2. 契约不变，仅改变请求的动作或约束，例如“整理邮件草稿”变成“把邮件发送给客户”。

保留“不应改变输出”的控制对：无关能力加入、名称改写、等价表述。评测模型是否该变时变、该稳时稳。

训练可先采用二分类/三分类 cross-encoder 加难负例。NLI 模型只能作为初始化或基线；“契约足以履行请求”不总是逻辑蕴含，不能把语义蕴含分数直接当履约概率。

创新边界：AgentAbstain 已有配对任务，Tool-REX 已有描述增强，ToolChoiceConfusion 已有契约。潜在区别是**以目录版本和职责编辑为干预单位，检验未见能力与版本迁移**，并给出干预正确性的人工证据。

这是低算力条件下最稳妥的起点，但数据质量要高于“让一个 LLM 自动生成并自动打分”。

### D. 等价能力感知的稳定拒答：避免“有多个答案就不敢选”

当两个能力都能满足请求时，Top-1/Top-2 分差小不应该自动触发澄清。可先识别请求条件下的功能等价，再在等价集合内依据非语义策略选取。

关键实验：逐步加入等价能力，测覆盖率是否不合理下降；加入真正冲突能力，测误路由是否上升。标签用有效能力集合，而不是唯一 ID。

ToolEX 已研究等价工具的标注，因此不要主张首次解决一对多。更值得做的是**等价集合对校准和目录扩容稳定性的影响**。注意工具等价依赖输入、输出约束和权限；不能仅凭名称相似进行全局合并。

### E. 澄清与升级的价值决策：作为后续课题

让决策层选择 `route / clarify / expand / defer`，比较每个动作的预期错误代价、交互成本与模型成本。可以从静态代价敏感决策开始，不必立即引入强化学习。

研究问题是：一次针对性追问是否比调用更大的模型更划算？哪些歧义只能由用户回答、不能靠更强模型消除？

模拟用户可以用于先导实验，但不能据此声称真实用户满意度提高。第一篇建议只记录澄清是否必要及理论上能区分哪些候选，不做完整对话代理。

## 6. 推荐方案：方法最小化，实验做扎实

建议链路：

```text
请求 + 必要上下文 + 目录版本
        ↓
程序过滤确定性不可用能力
        ↓
向量/词法混合召回（保留各阶段候选与版本）
        ↓
共享小模型逐项判断请求—能力适用性
        ↓
候选集合层的选择与接受策略
        ├ 自动路由
        ├ 扩大检索后再判断（预算允许）
        └ 不接受：无匹配 / 澄清 / 复合请求 / 外部升级
```

模型可从冻结 encoder + logistic gate 起步，再比较共享 cross-encoder。只在收益明确后尝试小型生成模型或蒸馏。优先选择当前已有、许可证允许且本地可运行的模型，正式实验前锁定 checkpoint；本报告不假定用户已拥有某种 GPU。

能力契约建议只保留影响判断的字段：`goal/actions`、`supported_inputs`、`excluded_scope`、`required_context`、`preconditions`、`effects`、`version`。确定性条件由代码核验；语言模型判断动作与语义限制，不负责授予权限。

输出至少区分：`retrieval_score`、`applicability_score`、`decision_status`、`catalog_version`、`calibration_version`。未经校准的适用性 logit 也必须叫分数，不叫正确率。

“轻量”用部署结果定义：记录模型参数、峰值 RAM/VRAM、batch=1 的端到端 p50/p95、每请求计算/调用成本、目录更新耗时。小模型需要逐个编码 K 个候选，K 增加后仍可能不轻。冷启动、预热后、缓存命中分别报告。

### 一个足够具体的首版算法

1. **构造训练对。** 正例为已审核的 `(x, d_c, applicable)`；负例各取一部分近邻错能力、同主题不同动作、输入限制冲突和真实 OOS。信息不足样本不强行标成永久不适用，可用第三类 `insufficient_context` 或先从二分类训练中分离。
2. **学习独立打分。** 首版用共享 cross-encoder 加交叉熵即可。下一版加入配对排序损失 `max(0, m − s_positive + s_negative)`；对无关描述改写可加分数一致性损失。所有新损失都要分别消融，不默认有效。
3. **学习接受 gate。** 在独立开发数据上，以“最终选择是否在有效集合内”为标签，输入 Top-1 适用性、Top-2 分数、检索器分歧、候选数、目录规模及是否涉及刚修改能力。先用 logistic regression，避免把系统复杂度藏在另一个大模型里。
4. **模拟历史更新。** 只在训练能力族上生成目录编辑，训练 gate 对编辑后的错误敏感；测试能力族及其编辑不参与训练。目录版本号只用于关联数据，不能作为可记忆的标签特征。
5. **更新后分配标签。** 将每次更新预算明确分成“诊断/训练”和“独立随机审计”两部分；与相同比例、相同总预算的随机采样基线比较。邻域样本用于改进模型，随机审计样本用于风险校准，不能混作同一统计用途。
6. **记录不能认证的情况。** 如果审计样本不足或上界超标，降低接受范围或返回升级；将损失的覆盖率计入结果。不宣称少量邻域样本已经恢复全目录可靠性。

这里的算法是一个待验证的研究起点。潜在方法贡献在第 4–5 步是否比现有更新策略更有效；第 1–3 步主要是建立有竞争力的基础系统。若总预算相同而随机审计占比过低，任何“省标注”收益都可能被无法认证抵消，这恰好是应被实验测量的取舍。

## 7. 理论部分：可严格做什么，哪些保证不能写

### 7.1 三种经常混淆的保证

1. **概率校准：** 报 0.8 的样本集合大约有 80% 正确；这是群体性质，不是每例真值。
2. **预测集覆盖：** 真实标签落入预测集的概率至少为 `1−α`。
3. **选择性风险控制：** 被自动接受的请求，其误路由率不超过 `α`。

第二项不自动推出第三项。即使只在共形集合为单元素时接受，所有错误也可能集中在这小部分样本上。例如总体 100 例、仅接受 10 例且其中 5 例错误，总体漏覆盖仍可能只有 5%，而接受风险是 50%。

类似地，阶段错误的联合界给出的通常是无条件错误概率；除以很小的接受覆盖率后，条件错误率仍可能很高。研究论文必须明确每个概率的分母和保证对象。

### 7.2 一个可实施的静态风险基线

先固定目录、模型、召回器和有限策略集合 `Λ`，这些策略的构造和排序不使用后面的校准标签。对独立同分布的校准请求，统计每个策略接受数量 `n_λ`、其中错误数量 `e_λ`。

用单侧 Clopper–Pearson 二项置信上界 `U_λ`，每个策略分配失败概率 `δ/|Λ|`。只部署满足 `U_λ ≤ α` 的策略，并在这些策略中选择覆盖率高的一个。由逐策略有效区间和 union bound，可在相应假设下得到同时有效的高概率控制；这是一条保守、可复现的基线，不是本报告声称的新定理。它与 Learn then Test 的思想相通。[LTT](https://arxiv.org/abs/2110.01052)

如果 `n_λ=0`，不把该策略当作已获得非平凡证书。如果在校准集上训练 gate、改提示词、挑特征，就不再满足“固定策略”的前提，应另划训练/调参数据或采用适当的选择校正。

样本预算有硬约束：固定单个策略、零错误、单侧 95% 上界为 `1−0.05^(1/n)`。要使上界不超过 1%，至少需要 **299 个已接受的独立校准请求**；若同时筛选 100 个策略并简单 Bonferroni 校正，则零错误情形至少需要 **757 个已接受样本**。这还没有计入拒答样本和分组需求。

因此先导研究可把 5% 风险作为主要操作点，1% 作为样本充分时的扩展，不要用几十条案例声称低风险保证。以上只是样本量演示，不是建议真实业务接受 5% 误操作。

### 7.3 目录变更为什么破坏原保证

删除有效能力可令同一句请求从 in-scope 变成 OOS；新增能力会改变胜者与竞争关系；修改职责会改变正确标签。因此，即使请求文本分布不变，`(请求, 目录, 有效标签)` 的联合分布也可能改变。

旧校准集不能默认延续有效。需要明确选择：

- **版本内保证：** 新目录下重新标注/重新判定校准标签，固定策略后校准；最稳妥。
- **更新分布内保证：** 将整次目录更新作为随机实验单元，并假设未来更新与校准更新可交换；样本量以独立更新数为核心。
- **在线长期保证：** 借鉴 ACI，但依赖持续反馈，且指标是长期频率，不能承诺更新后的短窗口风险。

从冲突邻域主动挑样本适合训练或诊断，**不能不加处理地用于代表全流量的二项风险证书**。最终证书仍需目标分布的独立随机审计样本，或使用适用的加权/抽样理论。拒答请求也要抽样标注，否则无法估计错误拒答及召回遗漏。

### 7.4 更偏理论的推进空间

可尝试建立“变更只影响局部决策区域”的条件，并证明未受影响区域可复用旧保证、受影响区域需重新校准。难点在于这个区域必须有可验证定义，不能仅凭 embedding 近邻断言其他请求不受影响。

一个用于理解问题的初等界：若固定规则在旧分布 `P` 下接受覆盖率为 `c`、接受风险不超过 `α`，且新旧完整样本分布总变差不超过 `ε<c`，则新分布的接受风险不超过

`min(1, (α·c + ε)/(c − ε))`。

推导：错误且接受的事件概率最多增加 `ε`，接受事件概率最多减少 `ε`，再取比值。它说明低覆盖率时小漂移也可能放大条件风险；它是标准概率不等式的直接推论，不构成创新。若更新同时改变规则，可在联合空间中显式编码目录和统一决策算法后再检查条件，不能直接沿用旧规则的界。

真正困难且有潜在贡献的是：从已知目录编辑和有限审计数据，得到比任意分布漂移更有用的可验证条件或标签复杂度界。总变差通常无法靠少量高维文本样本可靠估计，所以该公式首先是分析工具，不是上线证书。

若没有能力完成上述证明，建议将成果定位为“有统计校准支撑的方法与评测论文”，不要为了标题中的“理论”包装一个已有的 union bound。

## 8. 实验协议：如何证明不是工程堆叠

### 8.1 数据分三层

| 层次 | 来源与建议规模 | 能证明什么 |
|---|---|---|
| 公共意图层 | CLINC150；保留官方测试划分，再预先指定能力持出协议 | 已知/未知意图、少样本基础能力 |
| 公共工具层 | ToolRet / Tool-REX 的可控子集；保留来源与工具族信息 | 未见工具、近邻干扰和规模效应 |
| Intent Hub 动态目录层 | 先导 30–50 能力、600–1,000 请求；正式版按校准需求扩大 | 目录新增/删除/职责变更、中文请求与实际能力边界 |

这些规模是筹备建议，尚未采集。公共分类数据的标签描述不是天然完整能力契约；如需补写，应标明新增字段来源，并限制只能使用训练材料。不能查看测试请求后给契约补“答案提示”。

先导请求建议覆盖单一适用、近域不适用、远域不适用、信息不足、等价候选、复合请求。先导集用于暴露机制问题，不承担 1% 风险认证。

正式数据量从目标风险、接受率、目录版本数量反推。若需要多个版本分别给出低风险证书，1,000 条总样本通常不够。预算有限时，少做版本但每版标注扎实，比大量版本每版十几条更有说服力。

### 8.2 防泄漏划分

- 划分顺序为训练、调参、校准、最终测试；校准集不参与 gate 训练，测试集不参与阈值选择。
- 按能力族/工具来源持出，避免同一接口改个名字就同时出现在训练和测试。
- 同一原始请求的全部改写、最小对及目录变体放入同一数据分区。
- “目录更新回放”允许同一测试请求出现在多个版本中，因为要测变化；统计时按原始请求和目录更新聚类，不能把这些记录当独立新样本。
- 分开报告：未见措辞、未见能力、未见能力族、已知能力的新版本。这四者不是同一种泛化。

反事实评测和风险审计可以共享标签规范，但统计用途要分开：前者重在配对因果控制，后者需要符合部署目标分布的独立抽样。

### 8.3 必须有的强基线

| 编号 | 基线 | 目的 |
|---|---|---|
| B0 | 当前 Intent Hub 原始列表输出 | 报列表召回与列表精度，不擅自当成自动 Top-1 决策 |
| B1 | 当前链路 + 明确的 Top-1 接受策略 | 建立可比较的系统基线；标明新增策略并非原接口行为 |
| B2 | 相同 embedding + 全局阈值 / 每能力阈值 / margin | 判断收益是否只是阈值调优 |
| B3 | 相同召回 + 普通 cross-encoder reranker + 校准拒答 | 最重要的方法对照 |
| B4 | DNNC 风格成对判别；有充分类样本时加 ADB | 覆盖已有意图识别方法 |
| B5 | 小目录全量 LLM；大目录检索后 LLM，可输出无匹配 | 比较更强判别参照与成本，不称其为真实上界 |
| B6 | 共形预测集/Prune ’n Predict 思路 + 单独接受风险评测 | 防止把共形包装误当创新 |
| B7 | 固定阈值、全量再校准、相同预算随机再校准、滚动校准 | 验证动态目录和标注效率主张 |

若某论文代码或数据不可取得，应称为“基于其思想的基线”，不能冒称精确复现。Lee 的 2026 预印本在所查版本注明其目录和请求未公开，不应把未获得的数据列为已可复现资源。AgentAbstain 的作者仓库提供数据/环境，但说明生成管线未开放，不应预设可以直接运行 AbstainGen。[Lee 原文](https://arxiv.org/html/2609.18672v1)、[AgentAbstain 仓库](https://github.com/AntiQuality/agentabstain/blob/main/README.md)

### 8.4 动态压力测试

对每个固定测试请求池，预先生成多条目录演化序列：

1. 加入无关能力：理想结果基本稳定。
2. 加入相邻但不适用能力：检验竞争干扰与否定边界。
3. 加入真正适用能力：原先 OOS 应转为可路由。
4. 删除所有适用能力：原先可路由应转为不接受。
5. 修改职责：例如只读改为可写、支持格式收窄；同时设置不影响该请求的契约编辑。
6. 加入等价能力：允许选中任意有效项，测是否产生无谓拒答。

先从 20/50/100 能力规模做全量与检索对照，再在公共工具层增加到 1,000 以上；不必第一轮就运行 43k 全目录实验。召回 K 取 5/10/20/50 形成可比较曲线，所有方法尽量共用候选并另测端到端版本。

能力更新后的校准预算可取 0/20/50/100/200 条作诊断曲线，但这些小预算不保证能获得低风险证书。预算耗尽且无法认证时，报告无法认证及其覆盖率，不放宽统计标准换取“有效”。

### 8.5 指标及口径

| 指标 | 口径 |
|---|---|
| 有效能力召回 Recall@K | 在 `Y≠∅` 样本上，`R_K∩Y≠∅` 的比例；集合答案另报全覆盖 |
| 候选内选择准确率 | 仅在候选含有效能力时，选择是否属于 `Y` |
| 风险—覆盖率曲线 / AURC | 全链路报告；不同数据混合比例不直接比较 |
| Coverage@risk | 阈值由校准集决定，再在测试集报告实际风险与区间；不在测试集挑点 |
| OOS 误接受率 | 分近域/远域，分母为对应 OOS 请求数 |
| 错误拒答率 | 有有效能力但拒绝路由的比例，另拆召回遗漏与判别拒绝 |
| 更新回归率 | 旧目录判断正确、且新目录下该动作仍有效，却变错的比例 |
| 更新适应率 | 正确答案应变化的成对样本中，两端都正确的比例 |
| 校准恢复成本 | 恢复规定风险标准所需新标签数、时间、计算量 |
| 资源 | batch=1 的 p50/p95、内存/显存、模型调用次数、目录更新耗时 |

在同一流量、同一硬件、相同校准预算下比较。至少使用多个目录划分/变更序列；成对性能差异使用配对 bootstrap，按请求族或目录序列聚类。聚类 bootstrap 是性能不确定性分析，不等价于严格的二项风险证书。

### 8.6 最关键的消融

- 描述增强 vs 原描述：增加长度匹配的普通描述对照。
- 难负例 vs 同数量随机负例：排除单纯训练量收益。
- 独立适用性分数 vs 候选 softmax：在加入无关和相邻能力时分别测。
- 全局 gate vs 变化类型特征 gate：使用同样标注预算。
- 固定 K vs 自适应扩召回：匹配平均计算，并报告最坏延迟。
- 唯一 ID 标签 vs 有效能力集合标签：判断“提升”是否来自评价口径修正。
- 同模型、同训练数据的普通 reranker vs 提议方法：这是判断真正方法增益的核心。

## 9. 实施顺序、资源与决策门槛

以下按一名研究者、已有 Intent Hub 环境、可获得少量独立人工复核估算。没有假定现有标注集、GPU 或云额度。6–8 周是建立可判断实验结果的目标，不是发表承诺。

| 阶段 | 工作 | 完成与转向条件 |
|---|---|---|
| 第 1 周 | 锁定问题、目录版本与数据 schema；标注 100–200 条边界样本 | 若标注员无法稳定判断适用性，先修契约和定义 |
| 第 2 周 | 形成先导集；运行 embedding、普通 reranker、LLM 参照 | 若普通 reranker 已解决主要问题，转向动态再校准而非继续堆模型 |
| 第 3–4 周 | 实现动态目录回放、有效集合标签、配对评测 | 若没有可重复的更新退化，不主张动态问题严重 |
| 第 5–6 周 | 比较固定预算再校准与提议策略；做关键消融 | 若不优于随机采样/滚动校准，收缩算法创新主张 |
| 第 7–8 周 | 扩到独立能力族与公共数据，完成统计和资源评测 | 只有跨划分稳定才组织方法论文；否则交付诊断基准与系统报告 |

可预注册的继续投入门槛示例：在相同风险操作点下，覆盖率提高至少 3 个百分点且配对区间排除 0；或保持相同质量时，新标注需求减少至少 30%。**这些是研究管理目标，不是已有结果，也不是通用发表标准。** 先导样本太小时不根据显著性机械终止，应同时判断效应方向与数据瓶颈。

算力策略：第一轮使用冻结向量模型和小型门控，无需训练大模型；第二轮只微调一个共享判别器。最可能的瓶颈是可靠标签而非 GPU。先记录 100 条请求的实际速度，再估算全实验：`总耗时≈请求数×方法数×目录版本数×每请求平均耗时`，API 预算按实际输入输出 token 估算，不采用未核验价格。

## 10. 怎样组织一篇有竞争力的论文

### 推荐贡献表述（实验完成后才能采用）

1. 定义目录版本变化下的选择性能力路由，区分候选遗漏、真实不适用与等价能力。
2. 提供以真实契约为基础、请求与目录编辑成对控制的公开评测，采用能力族持出与集合真值。
3. 提出一个小型适用性判别与变更感知校准方法，在固定标注/计算预算下改善更新后的风险—覆盖率关系。
4. 在明确假设下提供风险控制说明；若有新证明，则精确说明超越既有校准理论之处。

推荐论文主线是“问题 → 现有方法在目录变更时出现何种可复现失效 → 一个最小方法 → 机制验证与成本收益”。Intent Hub 是实验载体与应用动机，不把产品功能数量当学术贡献。

### 三档可争取成果

| 结果强度 | 合理定位 |
|---|---|
| 只在本地几十个能力上优于原系统 | 工程改进、系统演示或案例报告 |
| 独立能力族与公共基准上稳定有效，有可靠动态协议与强基线 | NLP/IR 方法或评测论文的基础；可考虑 ACL 系列、EMNLP、SIGIR/CIKM 等相应研究方向 |
| 额外得到非平凡的变更结构假设、标签复杂度/稳定性保证，并有充分实验 | 更偏机器学习理论与可靠性的方法论文基础 |

这里是研究内容与社区的适配判断，不代表录用概率或投稿截止时间信息。

### 不建议作为主要卖点的内容

- “首次让路由器拒答”：已有大量先例。
- “首次使用能力契约/适用范围”：Tool-REX 与 ToolChoiceConfusion 已直接涉及。
- “首次区分选择和拒答”：2026-09 的直接工作已存在。
- “首次成对评测应行动和应拒答”：AgentAbstain 已覆盖。
- “首次支持多个正确工具”：ToolEX/ToolEQ 已覆盖。
- “模型输出 JSON 因此可靠”：格式合法与语义正确不同。
- “置信度高因此正确”或“共形预测保证任意动态目录安全”：不满足保证条件。
- “接上小模型比大模型省”：只有在相同质量约束和真实资源测量下才有意义。

**最终建议：先用两周验证“目录编辑确实导致固定阈值/普通重排的可靠性退化”，再投入动态再校准方法。若问题成立，这比泛泛做一个 Jev 风格语义路由器更有论文价值，也能直接指导 Intent Hub 的能力发布与回归机制。**
