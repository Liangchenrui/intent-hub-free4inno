# Jev 启发的轻量语义决策模型研究计划

版本：v0.1 · 2026-09-21  
状态：目标已澄清，研究方法和创新点待通过调研与实验确立。本文是研究开展计划，不代表已完成训练或验证。

## 1. 研究定位与已确定约束

本研究拟借鉴 Jev 将语言理解直接用于结构化决策的思想，以小型语言模型为起点，通过专项训练、知识蒸馏或模型结构调整，构建面向路由任务的高质量语义分类／决策模型。模型接收请求、上下文及运行时提供的候选描述，输出候选分数与选择结果，在保持必要语义理解能力的同时降低推理开销。

“具有 LLM 能力”在本研究中特指路由所需的语义、上下文、指令和条件理解，不要求同时保留开放问答、长文写作或完整 Agent 执行能力。

| 事项 | 当前约定 |
|---|---|
| 学位与研究要求 | 专硕；侧重算法与实验贡献，数学证明不是当前核心要求；不以额外发表论文为必然前提 |
| 时间约束 | 约三个月后开题，约一年研究与撰写窗口；本文按阶段完成条件推进，不编制精确时间线 |
| 主要应用 | 先研究按能力描述选择 Agent／Tool／Skill，后续再评估其他意图实体 |
| 新能力接入 | 尽量只提供描述即可接入，不针对每个新增能力重新训练 |
| 候选基模 | Qwen3-4B-Instruct-2507；可调整，不将 4B 或某个模型家族写成必要条件 |
| 算力 | 用户确认可稳定使用 5090，也可使用 A100；具体显存、数量、软件环境与占用尚待实验前核实 |
| 数据 | 接受公开数据、合成训练数据和少量人工标注 |
| 实证平台 | Intent Hub；用于工程基线、真实目录案例和系统集成验证 |
| 尚未确定 | 主要创新点、训练信号、模型结构、最终规模、教师模型及最终论文题目 |

**创新点不预先锁定为能力边界、拒绝路由、动态目录校准或推理加速。** 这些是可探索问题，只有文献比较和实验结果支持时，才升级为论文主线。

暂用工作题目：**面向智能体路由的轻量语义决策模型训练方法研究**。正式题目应在方法收敛后重写。

## 2. 任务定义与研究边界

设输入为请求及上下文 x、判断指令 q、候选描述集合 C={c₁,…,cₖ}，学习模型：

```text
fθ(x, q, C) → 候选分数 + 选择结果
```

候选描述至少包含稳定 ID 和能力说明。能力 ID 只承担映射作用，模型应主要利用文本语义。用于选择的分数、适用性估计和校准概率应明确区分，不能将 softmax 分数直接称为真实成功概率。

核心研究对象是“候选含义由输入描述决定的决策任务”。固定业务类别分类可用于检查训练流程，但不足以证明新增能力泛化。

### 2.1 分层处理任务难度

| 层次 | 场景 | 用途 |
|---|---|---|
| 基础层 | 完整信息、候选中至少有一个可行能力、单次选择 | 最先验证模型是否学会基本决策 |
| 泛化层 | 专项训练未见能力、跨领域描述、描述改写 | 验证目标中的即插即用能力 |
| 复杂语义层 | 否定、条件、范围限制、上下文、省略、相近职责 | 定位能力瓶颈，寻找改进空间 |
| 开放决策层 | 全部候选不适合、信息不足、多个可行候选 | 逐步验证可靠性；不要求全部成为独立算法模块 |
| 系统层 | 召回、候选选择、兜底、日志和延迟 | 验证 Intent Hub 中的实际影响 |

“未见能力”指在本研究专项训练中未出现，不承诺其从未进入基模预训练。多个候选都可完成请求时记录可接受集合；需要联合执行多个工具的任务另行标记，不能混同于多正确答案。

### 2.2 第一阶段不纳入的内容

完整多步规划、工具参数生成、真实执行结果预测、在线强化学习、通用 Jev 全功能复刻以及所有 LLM 的成本—质量路由，均不作为首轮必要目标。后续只有在核心决策模型已有证据且资源允许时扩展。

能力描述可能不完整或不真实。本研究首先评价“依据给定描述作出合理选择”，不能据此声称已保证实际执行成功。

## 3. 要逐步回答的研究问题

| 问题 | 需要的证据 |
|---|---|
| RQ1：现成小模型的分类决策能力和开销如何？ | 同一模型下生成式选择与直接评分的质量、延迟和失败分析 |
| RQ2：专项训练或蒸馏能否提升决策质量，同时保留未见能力泛化？ | 冻结能力划分，比较未训练、普通微调和候选方法 |
| RQ3：有效增益主要来自哪里？ | 同数据量、同模型、同预算下分离数据、训练目标、教师信号和结构贡献 |
| RQ4：能够以多小的模型、多低的推理开销达到所需质量？ | 多规模或多结构的质量—资源曲线，而非只报告参数量 |
| RQ5：离线优势能否转化为 Intent Hub 中的收益？ | 同输入同候选的回放与完整链路测量，分离召回和判别误差 |

先用 RQ1 建立证据，再围绕 RQ2/RQ3 选择一个主要方法问题；RQ4/RQ5 用于检验实际价值。不要求每个 RQ 对应一个创新点。

## 4. 文献与开源实现调研

### 4.1 按问题阅读，不按项目热度阅读

| 方向 | 重点理解 | 与本研究的联系 |
|---|---|---|
| Jev 与开放实现 | 接口、评分路径、训练声明、尚未公开部分 | 明确可借鉴思想和不可声称复现的边界 |
| 动态标签／零样本分类 | 如何将标签描述变成模型输入，如何处理未见标签 | 与描述驱动路由直接相关 |
| 工具检索与重排 | 请求—能力匹配、候选集合、描述质量 | 提供强基线及公开评测来源 |

| 高效判别结构 | 点式、成对、列表式评分；共享编码与候选交互 | 检验减少生成以外的效率空间 |
| 校准与选择性预测 | 分数是否可信、何时接受选择 | 作为可靠性评价基础，是否作为主方法待定 |

每篇关键论文记录：问题设置、监督来源、模型与损失、数据划分、对比基线、主要局限，以及与本目标的直接重叠。优先精读少量最接近的原论文和作者代码，再扩大范围。

## 5. 数据计划：先建立可信评价，再扩大训练

### 5.1 现有资产及用途

本会话先前只读核查的本地快照中，`routes.sqlite3` 有 8 个 active 实体、8 份描述、37 条正例、0 条负例；日志有 44 条 routing 记录和 2,987 条 runtime 记录。这些计数是本地快照，不代表生产规模，也不证明样例独立或标签正确。

当前目录以 SQLite 为准，旧 `routes.json` 不应作为唯一资产统计来源。现有正负反馈接口主要增删匹配样例，不能当作下游成功标签。重新导出实验数据时再次统计、去重和审核。

代码依据：[目录存储适配](../../intent-hub-backend/intent_hub/route_manager.py)、[预测服务](../../intent-hub-backend/intent_hub/services/prediction_service.py)、[反馈接口](../../intent-hub-backend/intent_hub/api/routes.py)、[日志服务](../../intent-hub-backend/intent_hub/services/log_service.py)。

### 5.2 三种数据来源

| 来源 | 主要用途 | 关键控制 |
|---|---|---|
| 公开数据 | 训练来源、可比较的外部评测 | 核查许可、保留原始划分和原始指标，适配版另标版本 |
| 合成数据 | 扩充训练覆盖、构造困难样例、提供教师监督 | 保存生成来源；去重、审核、控制模板和教师偏差 |
| 人工审核与 Intent Hub 案例 | 检查真实描述及关键难例 | 测试标签独立审核；敏感信息脱敏，不默认发送完整内部日志给外部教师 |

建议先制作数百条量级的人工审核诊断集，覆盖主要错误类型；用数千条量级训练样本检查学习趋势，再按学习曲线决定是否扩大。以上仅为启动规模建议，不是充分性承诺。低错误率结论需要根据样本量报告区间，不能用小测试集声称稳定达到 1% 风险。

### 5.3 样本应保存的内容

```text
sample_id、来源及许可、领域、能力家族
请求、必要上下文、判断指令
候选 ID 与描述、可接受候选集合、决策状态
教师输出及模型版本（如使用）、人工审核状态
原始样本/改写/对照样本的关联 ID、划分和数据版本
```

决策状态至少区分“存在可行候选”“无可行候选”“信息不足”；复合任务和描述欠明确样本单独标记。不要把这些情况全部粗略标成 NONE。

### 5.4 防止数据泄漏

1. **先按能力家族、来源或领域划分，再做生成和改写。** 同一能力的别名、翻译和近重复描述不能分散到训练与测试。
2. 分别维护训练、开发、必要时的校准集及锁定测试集。阈值和超参数仅在开发／校准集选择。
3. 设置已见能力新请求、未见能力、跨领域三类测试；未见能力是目标的核心证据。
4. 对照样本和描述变体按组划分；候选顺序随机化并检查 ID 泄漏。
5. 合成标签不能因教师给出就直接成为金标准；关键测试样本人工审核，争议样本记录依据或剔除。
6. 不用反复查看锁定测试错误来设计训练数据；错误发现主要在开发诊断集进行，必要的新测试集另行构造。

## 6. 技术路线与实验推进

### 阶段 A：任务与评测协议固定

完成任务定义、标注说明、数据划分及初始诊断集。首轮默认单次路由，中文为主要应用语言；若使用英文公开数据，分开报告，是否主张双语能力由后续结果决定。

**完成条件：** 每类样本都有可解释判定标准；能够说明新能力接入允许更新什么、不允许更新什么。主泛化测试冻结模型和已选阈值，允许提供和编码新描述。

### 阶段 B：建立未经专项训练的基线

先小规模跑通下表中的必要对比，再扩大数据。

| 基线 | 回答的问题 |
|---|---|
| 当前 Intent Hub 向量链路 | 相比现有系统改善在哪里？ |
| 描述向量检索 | 只依靠描述相似度能达到什么水平？ |
| 较小的交叉编码重排器／动态标签分类器 | 是否已经有更便宜的强判别方案？ |
| 同一 Qwen 的短答案生成式选择 | 小模型原有决策能力如何？ |
| 同一 Qwen 的直接标签 logits 评分 | 仅改变输出路径能带来多少收益？ |
| 较强 LLM 的选择结果 | 教师或强参考能解决哪些错误？不将其当作真值上界 |

公平设置：同输入、同候选、同上下文；避免让生成基线输出长解释而评分模型只输出答案。报告提示、模板、tokenization、精度、输入长度与解码配置。

直接 logits 原型先使用已核实为单 token 的标签，限制候选规模；不要未经检查扩展到多 token 标签。大目录实验可加召回，但先用给定候选任务隔离判别能力。

**完成条件：** 获得可靠的质量和开销基线，并能将主要错误归为语义误解、候选混淆、上下文不足、位置敏感、召回遗漏等。不能仅凭总体准确率选创新点。

### 阶段 C：建立普通专项训练基线

从最简单、可复现的监督训练开始，例如 LoRA／其他参数高效微调。先验证硬标签训练是否改善，并观察未见能力表现是否下降。LoRA 只是实现选择，不作为创新。

训练时变化候选数量、顺序和组合，避免模型记住固定槽位。多可接受候选应使用与标注相容的目标，例如将可接受集合的总概率作为监督，或使用多标签适用性目标；不要任意惩罚同样正确的候选。

**完成条件：** 能复现普通微调相对冻结模型的变化，且能区分训练失败、数据问题与泛化退化。若普通微调已充分解决目标，则检查是否仍存在值得研究的瓶颈，不强行拼接方法。

### 阶段 D：围绕实测瓶颈选择训练或结构改进

一次主要改变一个因素，以下路线不要求全部实现。

| 候选路线 | 适合的实测现象 | 最小对照及局限 |
|---|---|---|
| 教师硬标签／偏好蒸馏 | 教师在明确的一类错误上优于学生 | 对比同量普通标签与教师标签，排除只是数据增加 |
| 候选软分布蒸馏 | 教师分布可获得且有额外信息 | 对比硬标签；API 若不提供 logits，不把自报概率当作原始分布 |
| 推理过程辅助训练 | 学生在条件组合上失败，教师推理可审核 | 对比答案监督；训练中看推理不保证推理时免生成也能保留收益 |
| 对比／排序／边界样本训练 | 普通微调持续混淆相近候选 | 同量随机负例与困难负例对照，检查未见领域是否同样有效 |
| 候选感知决策头或共享编码 | 评分成本、候选交互成为主要瓶颈 | 固定数据与骨干，对比直接 logits 和普通判别结构 |
| 更小学生模型或压缩 | 4B 有效但部署开销偏高 | 分离专项训练、规模和量化的影响，报告质量代价 |

训练损失只在假设需要时引入。不预先叠加分类、蒸馏、校准、OOD 和效用等所有目标，也不因 Jev 提到 RLCD 就默认从强化学习开始。

**完成条件：** 选定一个主要贡献，能用“已有方法在 X 条件下存在 Y 问题，提出 Z，并通过指定对照验证”表达；增益超过随机波动，且不是只在一个合成模板上有效。

### 阶段 E：完整验证与稳健性分析

围绕已选方法补齐必要消融和外部评测，不无限扩展实验矩阵。最终核心比较至少重复多个训练种子，优先 3 个；固定种子记录并报告均值、波动或适当置信区间。相关样本的统计分析按能力／样本组处理，避免当成完全独立样本。

必要消融包括：无专项训练、普通微调、移除核心新组件；涉及教师时增加同预算监督对照；涉及结构时保持训练数据一致。检查候选顺序、数量和描述长度变化，确保优势不是输入格式偶然带来的。

**完成条件：** 主要结论能由独立测试和消融支持，失败案例及适用条件清楚，可复现实验材料完整。

### 阶段 F：Intent Hub 集成与论文整理

先通过独立实验代码完成训练与评测，再将选定模型以清晰接口接入。用同一批请求回放，先做离线／影子比较，避免为实验直接替换现用路由逻辑。

两组实验证据分别保留：一组给定相同候选，测模型判别；另一组接入真实召回与兜底链路，测系统收益。记录召回遗漏、选择错误和兜底开销。即使离线分数提高，也不能省略完整链路测试。

**完成条件：** 具有可运行原型、复现说明、方法和实验章节，以及明确局限。系统集成支持实用性论证，不替代算法贡献。

## 7. 评价口径与公平性

| 维度 | 首选指标／检查 | 注意事项 |
|---|---|---|
| 决策质量 | 可接受集合内的 Top-1 命中率，按领域／能力宏平均 | 多正确答案不能使用单一任意标签评判 |
| 泛化 | 已见／未见能力／跨领域分项结果 | 不以总体均值掩盖目标场景退化 |
| 复杂语义 | 否定、约束、上下文等诊断切片 | 诊断切片不能全部来自同一种生成模板 |
| 可靠性 | 无匹配误接受率、风险—覆盖率；必要时 Brier/NLL/ECE | 分数校准不等于执行成功保证，多标签与选择分布分别评价 |
| 效率 | p50/p95 延迟、吞吐、峰值显存、输入与输出长度 | 控制 GPU、批量、精度、并发、预热及缓存命中 |
| 训练代价 | 数据量、教师调用量、训练 GPU 时与峰值显存 | 不能只统计部署推理成本 |
| 系统价值 | Recall@K、候选内质量、端到端延迟及兜底比例 | 召回错误与选择错误分开 |

本地比较尽量在同一设备完成，5090 和 A100 的结果分开列；未核实硬件前不承诺全量微调或长上下文可行。云 API 的网络延迟与本地计算分别说明，不将跨环境对比归因为架构优势。

优先画质量—延迟、质量—显存曲线。若报告“接近教师”，应在开发阶段预定可接受差距；若报告“更低成本”，注明硬件摊销或云租赁口径，缺少可靠成本单价时先报告 GPU 时和资源消耗。

## 8. 创新点的选择与停止条件

研究贡献可以来自训练信号、数据构造与学习目标的结合、候选评分结构，或特定决策能力的迁移方法。研究型数据协议可作为支持贡献，但不能仅凭增加数据就宣称算法创新。

候选创新至少满足：有实测瓶颈；与最接近工作存在清晰差异；能在当前资源复现；核心组件可消融；收益在独立数据上成立。毕业要求最终还需结合导师与学院标准确认，本文不保证某种贡献组合必然满足要求。

| 观察结果 | 下一步决策 |
|---|---|
| 直接评分已足够准确，普通训练无收益 | 检查是否缺乏真实难例；若评价可信，转查压缩／计算瓶颈，不虚构训练优势 |
| 教师没有稳定优势 | 暂停该教师蒸馏，调整教师或选择其他方法 |
| 微调只提升已见能力 | 检查泄漏和记忆效应，调整划分、训练任务与监督；泛化恢复前不宣称成功 |
| 较小判别模型优于 4B | 将其纳入或转为骨干，不为保留 Qwen 而降低基线强度 |
| 收益只来自数据量 | 归因于数据，并继续验证数据方法贡献；不归因于新结构 |
| 核心消融无差异 | 删除无效组件或更换假设 |
| 系统耗时主要来自召回、网络或兜底 | 缩小模型加速结论，明确完整链路瓶颈 |
| 只在合成数据有效 | 优先补真实／独立来源验证，暂停扩大训练规模 |

## 9. 开题与最终论文应形成的材料

### 开题前的最小证据包

- 问题定义、研究边界与最接近相关工作的比较。
- 可审核的数据协议与已运行的基线。
- 主要错误及初步训练结果，包含负面结果。
- 一个主要方法假设、验证实验和失败后的替代路线。
- 数据、计算及标注可行性说明；仍未确认的内容明确标注。

开题不要求全部实验完成，但应能解释为何值得研究、具体如何验证、为何现有资源可以推进。

### 最终交付

数据版本和说明、训练与评测脚本、模型权重或适配器及许可说明、核心结果与消融、Intent Hub 集成原型、复现指南和学位论文。实验记录至少保存数据哈希、模型版本、代码 commit、配置、随机种子、硬件和原始结果。

论文可按“研究背景与任务—相关工作—数据与基线—核心方法—实验与分析—系统验证—总结与局限”组织，服从学院模板。章节数量与创新点数量不强行对应。

## 10. 下一步的具体起点

1. 对照阅读 OpenJEV 的实际评分路径、Qwen 模型接口和 GLiClass 的动态标签机制，写清输入、训练信号、评分计算和局限。
2. 选择一份公开数据候选，并从 Intent Hub 描述整理少量人工案例，建立首版诊断集与能力划分。
3. 在同一 Qwen 上运行短答案选择和直接 logits 评分，再加入一个较小判别基线，获得第一份错误分布。
4. 依据错误和教师差距，选择普通监督微调及一条最有希望的改进路线。

推进顺序是：**理解已有范式 → 建立可信评测 → 找到实测瓶颈 → 训练与改进 → 独立验证 → 系统与论文交付。** 当前无需提前确定最终创新点，也不应在缺少基线时投入大规模训练。
