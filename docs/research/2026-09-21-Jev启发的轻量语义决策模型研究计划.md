# 面向动态能力路由的轻量语义决策模型研究计划

版本：v1.0 · 2026-09-22  
状态：研究执行计划定稿；未完成模型训练、基线复现或方法有效性验证。本文确定研究边界、优先假设、实验顺序和完成条件，不预先宣称算法创新成立。

## 1. 研究目标与总体路线

以小型语言模型或较小判别模型为基础，研究依据请求、上下文和运行时能力描述进行直接评分的方法，用于选择 Agent／Tool／Skill。新能力尽量只通过提供描述接入，无须逐个重新训练；在保留必要语义理解的同时，获得可测量的质量与推理效率收益。

当前工作题目：**面向动态能力路由的轻量语义决策模型训练方法研究**。正式论文题目在核心方法经实验支持后确定。

研究优先顺序明确为：

1. 复现和比较已有决策范式，重点纳入 kev，建立普通专项训练基线。
2. 优先检验动态候选集合变化是否造成不合理决策，并研究相应训练方法。
3. 如果主要瓶颈是专项训练后的条件理解退化，则转向条件理解能力保持；不默认同时开展两条主线。
4. 完成独立测试、消融、效率测量和 Intent Hub 集成验证。

**拟解决的核心问题：当候选能力未见或集合发生变化时，如何训练轻量模型，使它在应保持决策的变化下保持稳定，在适用条件真正变化时正确调整选择？**

这一问题是优先研究假设，不是已经确认的文献空白。若普通微调或已有方法已充分解决，不继续为该方向增加无效模块。

## 2. 任务定义与边界

设请求及上下文为 x，判断指令为 q，候选集合为 C={c₁,…,cₖ}。每个候选包含稳定 ID 和能力描述；描述应说明功能、必要条件和限制，ID 仅用于映射，不应成为类别记忆捷径。

```text
fθ(x, q, C) → 候选分数、路由选择、必要的决策状态
```

“分数”“适用性估计”“选择概率”“经校准的正确率估计”分别定义，不能互换，更不能直接称为真实执行成功概率。模型只依据给定信息作出合理判断，不能保证描述真实或下游执行成功。

### 2.1 标注语义

| 状态 | 标注与期望行为 |
|---|---|
| 一个或多个能力可独立满足请求 | 标注可接受集合 A⊆C；选择任意一个符合任务约定的成员均可正确 |
| 所有候选均不适合 | A=∅，标注无匹配，期望拒绝自动选择 |
| 缺少决定适用性的必要信息 | 单独标注信息不足及缺失条件，期望澄清或转人工／兜底 |
| 必须联合执行多个能力 | 单独标记复合任务，首轮排除出单次选择主评测 |
| 描述不完整或有歧义 | 记录原因；人工无法判定的样本不强行分配唯一标签 |

多可接受候选不是信息不足；无匹配也不是信息不足。统一使用一个 NONE 标签或单一最大概率阈值，不足以证明这些状态已被正确区分。

“未见能力”指未进入本研究专项训练的能力家族，不承诺从未进入基模或公开 checkpoint 的预训练。使用 kev 等发布权重时，另行审查其公开训练来源；来源无法排除重叠的数据只作外部评测，不声称严格未见。

### 2.2 首轮不纳入的目标

完整多步规划、工具参数生成、执行成功预测、在线强化学习、通用 Jev 全功能复刻，以及 LLM 执行端的成本—质量路由，不作为必要研究内容。中文、英文结果分开报告，不预先承诺双语泛化。

## 3. kev 带来的基线与贡献边界

依据 2026-09-22 对官方 README、模型代码、训练代码及实验记录的阅读；以下为公开实现事实或作者报告，本研究尚未复现。正式实验固定 commit、模型 revision 和依赖版本。

### 3.1 可直接借鉴的基础

kev 使用语言模型骨干、LoRA 和 pointer head，根据决策位置与候选位置的表示计算候选分数，不依赖生成答案文本。运行时输入候选描述，使输出空间可以变化；结构支持变化不等于已经证明未见能力泛化。[模型实现](https://github.com/jaredpalmer/kev/blob/main/kev/model.py)

项目公开可训练模型、训练代码和评测资产，并区分多个问题的隔离与单个问题内部的候选交互。问题隔离不能直接推导出候选顺序不敏感。[项目说明](https://github.com/jaredpalmer/kev)

训练实现已有无匹配对照样本、置换一致性和分布锚定等机制；实验记录还探索过选项隔离，并报告过不同设置下的迁移和能力保持问题。[训练代码](https://github.com/jaredpalmer/kev/blob/main/kev/train.py)、[实验记录](https://github.com/jaredpalmer/kev/blob/main/PLAN.md)

### 3.2 不单独作为创新的内容

- 小模型＋LoRA＋评分头，或把生成输出改为直接打分。
- 新增 NONE 标签、随机打乱候选、普通置换 KL 或普通分布保持 KL。
- 仅替换骨干、扩大数据、调整学习率、增加温度校准。
- 提供 Jev 风格接口、中文封装或接入 Intent Hub。

这些可以成为必要基线或实现组件。只有解决明确不足，并通过相关工作比较和控制实验，才可能构成方法贡献。

## 4. 研究问题与优先方法假设

| 问题 | 主要证据 | 角色 |
|---|---|---|
| RQ1：现有方法在未见能力与目录变化下有哪些稳定缺陷？ | 基线、普通微调、按错误类型划分的诊断结果 | 选题依据 |
| RQ2：变化感知训练能否改善应保持／应改变两类行为？ | 同数据、同骨干、同预算对照和核心消融 | 优先方法问题 |
| RQ3：改进是否保留条件理解及未见能力泛化？ | 能力家族隔离、未见条件组合、训练前后比较 | 必要质量约束；退化显著时转为备选主线 |
| RQ4：质量收益是否具有可接受的资源代价并能进入真实链路？ | 质量—资源曲线、候选内与端到端实验 | 实用性验证 |

### 4.1 优先方向：动态候选集合下的稳定决策

对同一请求构造关联候选集合 C 与 C′，人工审核变化后的正确标签。候选稳定性必须服从任务语义，而非一律要求输出不变。

| 变换 | 预期行为 | 评测要求 |
|---|---|---|
| 候选顺序置换 | 在映射回稳定 ID 后保持合理选择 | 单正确样本检查翻转，多正确样本按可接受集合评价 |
| 加入／删除明确无关的候选 | 原有可接受性不变 | 同时报变化前后正确率，避免稳定地选错也获高分 |
| 加入语义等价且可独立完成任务的候选 | 可接受集合扩大，可以重新分配选择 | 评价等价组命中，不强制原 ID 或各项概率不变 |
| 删除唯一正确候选 | 从可选择转为无匹配 | 评价状态转换；删除部分正确候选时仍应选择剩余成员 |
| 修改能力范围、权限或前提条件 | 根据新条件重新判断 | 对照两侧都正确才算成功 |
| 加入相近但不满足关键条件的候选 | 保留正确能力，识别近邻边界 | 与普通随机负例、同量困难负例训练比较 |

softmax 选择概率满足 pᵢ=exp(sᵢ)/Σⱼ∈C exp(sⱼ)。即使原始分数不变，候选增加也会改变分母；选择概率下降不等于能力适用性下降，候选交互还可能改变原始分数。

**候选方法假设：**通过分别建模能力适用性与集合内选择，并对不同目录变换施加符合语义的监督，改善未见能力场景中的稳定性和状态转换。

最小推进顺序：先在现有评分模型上做变化感知数据训练；若与同量普通增强相比仍存在明确局限，再验证是否需要适用性与选择分离的结构。不要一开始同时叠加多个头和多个损失。

如探索适用性分支，应明确其标签针对给定请求与描述、允许多项同时适用；信息不足不能直接作为负例。集合内选择可使用可接受集合总概率的负对数作为基础监督。变化约束仅施加于语义允许不变的部分，跨不同集合的分布先按 ID／等价组对齐，不对所有输出直接套 KL。

分离适用性与选择本身并非已确认的新方法。贡献需落到具体变换建模、学习目标或评分机制，并解释超出已有多标签分类、重排和一致性学习的部分。

### 4.2 备选方向：专项训练中的条件理解能力保持

**启动条件：**基线与普通微调比较表明，主要错误来自否定、条件组合、范围限制或上下文理解，并且训练后退化在独立切片和多个种子下可复现；目录变化本身不是主要瓶颈。

先区分基模原本不会、评分路径读不出、专项训练后遗忘三种原因，再设计保持或迁移方法。若同骨干生成和直接评分都不会，不能把问题称为训练遗忘。

候选路线是用经过审核的条件判断辅助监督或对照训练，让学生在直接评分时保留这些能力。与答案监督、同量样本增强、普通分布锚定和低学习率基线比较；教师解释或自报置信度不能直接视为正确推理或原始概率。

重点验证未见条件组合，不仅测试熟悉模板的新措辞；推理时如果仍需要额外生成或教师调用，计入资源成本。该方向若成为主线，应相应改写 RQ2 与论文题目，不并行堆叠两套方法。

## 5. 数据与评价协议

### 5.1 数据来源与规模

采用公开数据建立外部可比较性，合成数据构造训练覆盖，人工审核与 Intent Hub 案例校验关键语义。公开检索数据适配为候选内选择后另标版本；保留原始划分、来源和许可。

启动规模为数百条独立请求的人工审核开发诊断集，再按变换生成关联样本；训练先用数千条量级检查学习趋势。这里的数量是启动预算，不是低风险结论的充分样本量。变换版本数量不能冒充独立请求数量。

Intent Hub 的实体、描述、正负样例与日志在实际导出时重新统计。旧计划记录的计数仅为历史快照，不作为当前规模或执行标签。现有反馈接口不能自动解释为下游执行成功标注。

代码入口：[目录存储](../../intent-hub-backend/intent_hub/route_manager.py)、[预测服务](../../intent-hub-backend/intent_hub/services/prediction_service.py)、[反馈接口](../../intent-hub-backend/intent_hub/api/routes.py)、[日志服务](../../intent-hub-backend/intent_hub/services/log_service.py)。

### 5.2 数据字段

```text
sample_id、group_id、来源、许可、语言、领域、能力家族
请求、上下文、判断指令、候选 ID 与描述版本
可接受集合、决策状态、缺失条件、等价候选组
变换类型、变换前关联 ID、变换后标签及审核依据
教师与生成版本、人工审核状态、划分、数据版本
```

描述长度与信息完整性作为独立因素控制。方法不能读取完整文档，而基线只读取省略限制的短描述；需要补充描述时，所有对照获得相同信息，并单独评价描述增强收益。

### 5.3 划分与泄漏控制

1. 先按能力家族、领域和来源确定训练／开发／校准／锁定测试，再生成改写和对照。候选描述的别名、翻译、近重复及关联变体同组划分。
2. 分别报告已见能力新请求、未见能力、跨领域；条件组合泛化还须保留未见组合结构。
3. 诊断错误用于开发，不用锁定测试错误反向设计训练样本。方法和超参数在开发／校准集确定后才进行最终测试。
4. 阈值仅在校准数据上选择；主泛化测试冻结模型和阈值，允许输入及编码新描述。允许重新校准的实验另列，不与零更新接入混报。
5. 审核等价、无关与适用性等变换前提；优先采用独立复核，争议标签保留依据或排除。合成教师输出不是金标准。
6. 统计区间按独立请求／能力组重采样，不能把同源变体当作独立观测；公开 checkpoint 的训练重叠单独披露。

## 6. 基线、消融与公平比较

### 6.1 两层比较

**现成方案比较**回答实际采用什么：比较当前 Intent Hub、描述向量检索、一个较小重排／动态标签模型、kev 发布模型与较强 LLM 参考。它们已有训练经历不同，效果差异不能单独归因于结构。

**受控方法比较**回答为什么有效：尽量保持相同骨干及 revision、数据划分、描述信息、训练预算和推理设置，比较短答案生成、标签 logits、pointer head 普通训练和拟议方法。kev 发布权重继续微调的实验，与原始骨干起训的实验分别记录。

### 6.2 分阶段最小对照

| 对照 | 用途 | 开展阶段 |
|---|---|---|
| 当前系统与描述向量检索 | 确定工程起点与纯相似度能力 | 首轮 |
| 较小重排器／动态标签模型 | 防止遗漏低成本强基线；核对中文覆盖 | 首轮 |
| 同骨干短答案生成、直接 logits | 分离生成路径与直接评分效果 | 首轮 |
| kev 发布权重 | 建立可运行决策模型参考 | 首轮 |
| kev 普通路由微调 | 判断简单适配是否已解决目标 | 普通训练阶段 |
| 同量普通增强、困难负例、置换训练 | 排除只是数据增加或顺序随机化 | 优先方法阶段 |
| 变化感知训练与其核心消融 | 验证新增机制 | 优先方法阶段 |
| 同骨干普通 pointer head 与拟议结构 | 分离结构和训练信号贡献 | 仅在提出结构改进时 |
| 较强 LLM／教师 | 定位能力差距，不作为金标准或理论上界 | 代表性诊断子集；必要时扩展 |

最终核心比较优先使用 3 个训练种子；初步筛选可用单种子，但不据此确认微小提升。资源不足时缩小方法数量，保留强基线和关键消融。

生成基线只输出必要答案，不强制长解释。直接 logits 需核实标签 tokenization，多 token 标签不得按单 token 分数随意比较。性能测试固定精度、候选数、输入长度、批量、并发、预热与缓存条件，记录失败和截断。

## 7. 指标与判定口径

| 维度 | 指标与口径 |
|---|---|
| 决策质量 | 可接受集合内 Top-1 命中率，按能力／领域宏平均；无匹配和信息不足分开评价 |
| 目录稳定性 | 单正确样本的错误翻转率，以及多正确样本的可接受集合命中；同时报告变换前后准确率 |
| 正确响应变化 | 删除唯一正确候选后的无匹配识别率；条件变化对照的双正确率 |
| 泛化与能力保持 | 已见／未见能力、跨领域、未见条件组合分项结果及训练前后差值 |
| 可靠性 | 无匹配误接受率、信息不足误路由率、风险—覆盖率；适用时报告 Brier／NLL／ECE |
| 效率 | p50/p95 延迟、吞吐、峰值显存、输入长度、实际调用次数 |
| 训练成本 | 数据与审核量、教师调用量、训练 GPU 时、峰值显存、总训练 token 或可比较计算量 |
| 系统价值 | Recall@K、候选内命中率、兜底／澄清比例、端到端正确率与延迟 |

选择性风险定义为自动接受样本中的错误比例，覆盖率为自动接受样本占全体样本的比例。无匹配或信息不足样本被错误接受也计入风险。阈值在校准集选择，在测试集报告实际风险及区间；测试曲线上事后寻找最优阈值不能冒充可部署保证。

多可接受候选不默认具有均匀的真实偏好分布；未经明确目标定义，不对它们使用任意单标签 Brier／ECE。低最大选择概率不自动代表应该拒绝，等价候选可能分担概率。

主方法晋级前，在开发阶段写明最低有用改进幅度、允许的质量退化和资源预算，并冻结；数值根据基线波动、样本量和应用需求确定，不在看到测试结果后调整。结论同时报告效应大小和不确定性。

## 8. 执行阶段与完成条件

| 阶段 | 具体工作 | 完成条件 |
|---|---|---|
| A：证据与协议固定 | 精读 kev 评分／训练路径；比较最近相关工作；核对算力、许可；定义标签、变换和数据划分 | 明确可复用组件、待验证差异及版本；诊断样本可人工复核 |
| B：基线诊断 | 运行首轮基线；测基础选择、未见能力、目录变化和条件切片 | 得到可复现错误分布和资源数据，定位主要瓶颈而非只看总体准确率 |
| C：普通专项训练 | kev 普通微调；候选随机化与常规数据增强；检查能力保持 | 能区分简单适配收益、泄漏、训练失败与真实泛化退化 |
| D：单一主方法 | 默认检验变化感知训练；必要时再做结构；符合启动条件才转备选主线 | 与最接近方法有明确差异；同预算对照和消融支持核心机制 |
| E：独立验证 | 多种子、锁定测试、外部来源、候选数和描述长度等必要稳健性实验 | 增益超过波动且适用边界清晰；失败案例和负结果保留 |
| F：系统与论文 | 独立模型服务、离线／影子回放、完整链路比较、复现与论文整理 | 模型证据与系统证据分别成立，产物与许可完整 |

进入阶段 D 前只选一个主方法假设。阶段 E 的测试结果用于确认或否定结论，不继续围绕同一锁定测试迭代；若需要重新研究，应建立新的独立最终评测。

### 8.1 最先执行的四项工作

1. 固定 kev 代码与权重版本，梳理输入格式、pointer head、普通训练和已有一致性机制，完成小样本加载与评分检查。
2. 选择一个公开数据来源，并从 Intent Hub 整理人工案例；按能力家族划分，构造六类目录变换的开发诊断样本。
3. 跑通 kev、同骨干两种输出路径及一个较小判别基线，记录同候选质量和实际资源消耗。
4. 运行普通路由微调，对照诊断结果决定是否推进变化感知方法，或触发条件理解备选路线。

本计划定稿不等于这些实验已经完成，也不授权额外云端付费、大规模训练或生产替换。

## 9. Intent Hub 验证方式

先在独立实验代码中训练与评测，再以稳定接口集成。至少返回候选 ID、评分类型、选择及状态、模型和目录版本，并记录各阶段耗时；未校准分数必须明确标识。

两组实验分别报告：

- **给定候选实验：**所有模型读取相同候选和上下文，测判别质量；可另设保证正确能力在候选内的诊断集，并明确该限制。
- **完整链路实验：**使用真实召回结果和拒绝／兜底策略，召回遗漏照实计入端到端错误，记录 Recall@K、选择错误、兜底代价及总体延迟。

首先离线或影子回放，不直接替换现用路由。实体描述、正负样例和现有阈值属于不同输入来源，比较时记录是否使用。若模型加速未转化为整体加速，按实测报告召回、网络或兜底瓶颈。

## 10. 停止条件与方向调整

| 观察结果 | 决策 |
|---|---|
| kev 普通微调已解决主要目录变化问题 | 不继续强加结构；检查是否仍有独立且有价值的瓶颈 |
| 目录变化缺陷不明显，条件理解退化稳定存在 | 按第 4.2 节转向能力保持，更新主问题与实验矩阵 |
| 变化感知方法不优于同量普通增强／困难负例 | 不把数据量收益解释为新目标或结构收益 |
| 等价候选加入导致概率变化但选择仍合理 | 修正错误的评测目标，不将合理变化作为缺陷 |
| 只提升已见能力或单一合成模板 | 暂停扩大训练，先排查记忆、划分和模板偏差 |
| 核心消融无差异、提升处于种子波动内 | 删除无效组件或否定假设，不通过挑选种子宣称成功 |
| 教师无稳定优势，或监督无法审核 | 停止该教师蒸馏，改用可验证监督或其他路线 |
| 更小判别模型更优 | 采用更合适的骨干，不为保留 4B／Qwen 降低比较标准 |
| 现有路线均无明确方法空间 | 回到相关工作与错误分析收敛新假设，保留负结果，不将工程接入包装成算法创新 |

## 11. 开题与最终交付

### 开题前

形成问题定义及最接近工作的差异表、数据与评价协议、实际运行的基线与普通微调结果、一个有证据支持的主要方法假设、关键对照与停止条件，以及算力和标注可行性说明。开题不要求全部实验完成，但应说明为什么值得研究、如何验证及失败后如何收敛。

### 最终交付

- 经版本化的数据及来源／许可说明，按组划分和审核记录。
- 训练、评测、消融与统计脚本；模型权重／适配器和复现指南。
- 原始结果及配置：数据哈希、模型 revision、代码 commit、随机种子、硬件、依赖与计算开销。
- 一个经过独立测试支持的核心方法结论，包含负结果、适用条件和局限；若假设未获支持，如实调整研究结论。
- Intent Hub 集成原型与候选内、端到端两层验证。
- 学位论文，建议按“任务与相关工作—数据与基线—核心方法—实验分析—系统验证—局限”组织，服从学院模板。
