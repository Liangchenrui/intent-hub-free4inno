# 轻量语义决策与 Agent 路由：相关论文、公开模型与研究启发

调研日期：2026-09-21。依据：[研究计划](2026-09-21-Jev启发的轻量语义决策模型研究计划.md)与[Jev 技术路线报告](../Jev%20技术路线完整调研报告.md)。

本文围绕已澄清的目标：把小型语言模型训练成擅长语义理解与选择的决策模型，首先用于按运行时能力描述选择 Agent／Tool／Skill，新增能力尽量不重新训练。创新点仍待实验确定。

证据说明：这是一份定向叙述性调研，不是穷尽式系统综述。论文数值均为作者报告，本次没有下载运行模型、复现训练或测试 Intent Hub 收益。正式发表、预印本、项目发布分别标注；仓库可访问不等于完整训练可复现。本文由 AI 辅助检索与归纳，主要事实链接至论文、作者仓库和模型卡。

## 1. 结论：有人在做，而且已经出现直接相近的路线

你的总体构想具有可行性，但“用小模型理解候选描述，直接输出分类或路由分数”已经不是空白。已有工作覆盖了其中多个关键部分：

| 你的设想 | 已有代表 | 重叠判断 |
|---|---|---|
| 类别在推理时由描述给出，无须每换类别就重训 | UniMC、GLiClass、NLI 通用分类器 | 很高；动态标签分类已有成熟研究脉络 |
| 保留语言理解能力，直接打分，减少长文本生成 | ModernBERT-Instruct、Qwen3-Reranker、Jina reranker | 很高；编码器和解码器都能实现 |
| 用小型 Qwen 加判别模块做路由 | SCX Router | 架构设想很接近，但主要选择 LLM 执行端 |
| 专门训练工具／技能选择模型 | Tool-REX／ToolRank、SkillRouter、SkillRet | 应用目标直接重叠，已有权重和评测资产 |
| 从强教师迁移判断能力，推理时只输出决策 | Distilling Step-by-Step 等蒸馏路线 | 基本思想已有；需要提出更具体的训练改进 |
| 用 Jev 风格 API 暴露机器可消费的判断 | OpenJEV、SemIf、openjev-sglang | 主要是推理接口和服务实现，训练成果不能据此推定 |

上述判断的来源与具体边界见第 3—6 节。**研究仍值得推进，但论文贡献应从“做出一个这样的模型”收敛为“解决已有模型在某种可验证条件下的不足，并证明改进来自所提方法”。**

目前最值得优先检验的问题是：当候选在训练时未见，且选择依赖条件、否定、上下文或相近职责时，怎样训练小模型，使它更接近教师的判断，同时保持直接评分的低推理开销？这是一条候选主线，不是本调研已经证明的新颖性结论。

## 2. 先区分四种经常被统称为“路由”的任务

| 任务 | 模型要回答什么 | 主要监督与评价 | 与本研究关系 |
|---|---|---|---|
| 动态标签分类 | 请求符合哪些文字描述的类别？ | 语义标签、F1／分类正确率 | 方法基础 |
| 工具／技能检索 | 大目录中哪些能力值得进一步考虑？ | 相关性、Recall@K／NDCG | 上游召回及一部分选择问题 |
| 候选内能力决策 | 给定候选中，谁满足请求及其限制？ | 可接受候选集合、选择正确率 | 当前核心 |
| LLM 成本—质量路由 | 哪个模型执行后效果好且成本合适？ | 实际输出质量、价格／延迟 | 相邻方向；不能直接替代能力选择实验 |

例如，SCX Router 与你的模型结构愿景接近，但模型名称可被输入不代表系统已知道全新模型的真实能力；Qwen3-Reranker 会打相关性分数，也不代表已经掌握业务适用条件。反过来，ToolRet 的检索收益不能直接等同于最终执行成功。

本研究还应区分：多个候选各自都能完成任务，与必须联合使用多个工具。这两种情况需要不同的标签与评价。

## 3. 动态标签与小型语言决策模型：最接近的技术基础

### 3.1 UniMC：将各类理解任务统一成选择题

**发表状态：EMNLP 2022 主会。** [论文及出版信息](https://aclanthology.org/2022.emnlp-main.474/)。

UniMC 将不同自然语言理解任务组织成统一的多项选择格式，使用 BERT 类模型，在选项标记位置学习判断，而不是为每个任务训练固定类别头。论文包含选项预测及相关训练目标，并调整注意力掩码，限制选项之间的相互干扰。[论文全文](https://aclanthology.org/2022.emnlp-main.474.pdf)。

**对你的启发：**“动态候选＋小模型判别”至少在这条路线中已经有正式发表的先例。值得复用其任务统一方法，并检查它在能力描述较长、类别相近、带上下文的路由上是否仍成立。论文中的零样本 NLU 结果不能直接视为 Agent 路由结果。

### 3.2 GLiClass：直接面向运行时标签的通用分类器

**状态：2025 年预印本；代码与模型公开。** [论文](https://arxiv.org/abs/2508.07662)、[代码](https://github.com/Knowledgator/GLiClass)。

它联合编码文本和标签，通过标签／文本表示计算分类分数；标签可以在推理时传入。论文还比较不同编码结构，并使用通用分类、NLI 等数据及后续训练。论文所报 439M 模型的跨任务平均 F1 为 0.7193，对照中最强 NLI 模型为 0.6821，即约 **3.72 个百分点**，不是提高 5.5 个百分点。这些是通用分类任务结果。[论文方法与表格](https://arxiv.org/html/2508.07662v1)。

**对你的启发：**它应成为重要基线。只与大模型生成答案或简单 embedding 比较，会漏掉直接竞争者。也应保留“几亿参数编码器已经足够”的可能性；4B 是候选方案，不是研究前提。中文实验需核对所选 checkpoint 的语言覆盖，不能拿主要面向英语的模型直接证明编码器路线无效。

### 3.3 ModernBERT-Large-Instruct：用单个答案 token 实现指令分类

**发表状态：Natural Language Processing Journal，2025 年第 11 卷，100150。** [出版方页面](https://www.sciencedirect.com/science/article/pii/S2949719125000263)。论文题为 *It is all in the [MASK]: Simple instruction-tuning enables BERT-like masked language models as generative classifiers*。

作者从 FLAN 中抽取适合单 token 答案的任务，使用约 0.4B 的 ModernBERT，并利用 MLM 头完成答案预测，无须为每项任务增加专用分类头。公开权重可用。[模型卡](https://huggingface.co/answerdotai/ModernBERT-Large-Instruct)、[预印本](https://arxiv.org/abs/2502.03793)。

**对你的启发：**“有指令理解能力的分类模型”不一定必须保留自回归生成形态。可以把它作为结构对照，但单 token 分类和复杂候选语义判断仍有差别；通用理解测试成绩不能替代未见能力实验。

### 3.4 Qwen3-Reranker：你可以立即比较的解码器评分路线

**状态：2025 年技术报告，模型与推理代码公开。** [技术报告](https://arxiv.org/abs/2506.05176)、[官方仓库](https://github.com/QwenLM/Qwen3-Embedding)。

Qwen3-Reranker 提供 0.6B、4B、8B 规模。官方实现接收 instruction、query、document，读取最后位置的 yes／no logits 并归一化为分数，无须生成一段解释。其专门训练说明，“从语言模型变成评分器”已经有现成起点；Embedding 与 Reranker 的训练流程应分别理解，不要混用两者的成果。

**对你的启发：**把能力描述作为 document 是自然的初步适配。应比较原始 Qwen3-4B-Instruct 直接评分、现成 Qwen3-Reranker，以及你训练的版本，从而判断收益来自专门训练还是仅仅换了输出方式。分数也不自动等于真实执行成功概率。

### 3.5 Jina reranker v3／v3.5：联合候选评分与小模型蒸馏

**状态：技术报告与公开权重，未在本次核实正式会议发表。** v3 在同一上下文中处理请求与多个候选，通过表示和评分模块完成 listwise 排序。[作者介绍](https://jina.ai/news/jina-reranker-v3-0-6b-listwise-reranker-for-sota-multilingual-retrieval/)。

v3.5 继续采用 0.6B 规模，结合混合注意力与自蒸馏。模型卡报告在其统一检索协议下，相对 v3 有质量提升，并在 A100 上取得 1.22—1.56 倍推理加速；这是特定输入与实现下的结果，不能直接移植为 Intent Hub 延迟预期。权重采用 **CC BY-NC 4.0**，不应笼统称为可任意商用的开源模型。[模型卡与结果口径](https://huggingface.co/jinaai/jina-reranker-v3.5)、[方法介绍](https://jina.ai/news/jina-reranker-v3-5-faster-listwise-reranking-hybrid-attention-self-distillation/)。

**对你的启发：**候选联合比较、稀疏注意力、蒸馏各自已有先例。可研究它们在路由中的具体权衡，但不能仅把几个成熟组件组合起来便认定为算法创新。

### 3.6 SCX Router：与“训练一个小型 LLM 路由分类器”很接近

**状态：2026-09-02 预印本。** [论文](https://arxiv.org/abs/2609.02292)。

它把 Qwen3 解码器与浅层双向评分模块结合，约 0.6B，不生成路由文本，支持运行时标签。会话文本保留 KV cache，候选标签作为临时后缀评分。作者在所选 1,000 个任务上报告综合得分 0.707，对照最强固定模型为 0.696；不能把它写成普遍显著超越最强模型。[方法与实验](https://arxiv.org/html/2609.02292v1)。

**公开进度：**[模型卡](https://huggingface.co/scx-admin/scx-router-v0.1)可访问，给出 GLiClass 加载与流式调用示例；论文列出的独立仓库 `Knowledgator/GLiClass-Model-Router` 本次返回 404，通用 [GLiClass 仓库](https://github.com/Knowledgator/GLiClass)可访问。模型卡还提示部分端到端结果并非对最新 checkpoint 重新测得，复现时须固定版本。

**对你的启发：**这是架构层面的直接相近工作，必须进入开题相关研究。其核心实证是 LLM 执行端选择，尚不能据此确认它能零样本理解新 Agent／Tool 的完整能力限制。此差异需要实验验证，不能直接宣布是研究空白。

### 3.7 其他值得保留的基础工作

| 工作 | 核实状态与做法 | 用处 |
|---|---|---|

## 4. 专门做 Tool／Skill 选择的工作：最直接的应用竞争者

### 4.1 ToolRet：检索模型在工具场景中并非天然有效

**发表状态：Findings of ACL 2025。** *Retrieval Models Aren’t Tool-Savvy: Benchmarking Tool Retrieval for Large Language Models*。[论文与出版信息](https://aclanthology.org/2025.findings-acl.1258/)。

该工作构建约 7.6K 任务、43K 工具的检索基准，考察常见检索模型在工具场景中的表现，并研究专门适配。它给你的价值主要是公共任务、候选目录与可比较协议。

**启发：**保留原始检索实验，再单独构造候选内选择实验。若使用人为保证正确工具在内的小候选集，应明确这是“候选内能力”，不能报成全目录效果。

### 4.2 Tool-REX／ToolRank：已有 4B 专用工具排序模型

**发表状态：ICLR 2026。** *Tools are under-documented: Simple Document Expansion Boosts Tool Retrieval*。出版信息由作者仓库论文条目及[会议论文列表](https://iclr.cc/virtual/2026/papers.html)交叉核对。[作者仓库](https://github.com/EIT-NLP/Tool-REX)。

其核心包括利用 LLM 补充工具功能、适用条件、限制及标签，再进行检索／排序训练。仓库提供扩展数据及 ToolEmbed、ToolRank 系列；[Tool-Rank-4B 权重页](https://huggingface.co/Lux1997/Tool-Rank-4B)可访问，但该页说明较少，不能把权重可用等同于训练全链路已复现。

**启发：**“微调一个 4B 模型专门选工具”已有直接参照。还须区分模型方法贡献与描述补充带来的信息收益。若你用教师生成更完整描述，而基线只读原始短描述，性能差异不足以证明学生训练更好。

### 4.3 SkillRouter：小检索器＋小排序器已进入大规模技能目录

**状态：2026 年预印本，本文以 v5（2026-07-20）为准。** [最新摘要](https://arxiv.org/abs/2603.22455)、[v5 全文](https://arxiv.org/html/2603.22455v5)、[公开仓库](https://github.com/zhengyanzhao1997/SkillRouter)。

它使用 0.6B 检索器和 0.6B 排序器，利用 Skill 正文、困难负例与排序训练。作者在约 80K 候选技能目录中报告 74.0% Hit@1。需特别注意：**80K 是候选规模，核心人工验证查询只有 75 条**，另有合成补充集，不能写成在 80K 测试请求上验证。

论文的一个关键发现是：在其高度重叠目录中，仅用元数据、去掉正文会明显掉分；将正文浓缩成元数据仍不能完全恢复效果。公开仓库定位为评测发布，包含评测与模型入口，不应据此宣称完整训练过程都已开放。

**启发：**“只提供描述即可接入”可以保留，但必须约定描述包含什么。正文中有而描述中没有的事实，模型无法可靠凭空恢复。应比较短描述、完整能力文档和固定预算的压缩描述，判断瓶颈究竟是缺信息还是不会判断。

### 4.4 SkillRet：与你的数据需求高度契合

**状态：2026 年预印本，本文采用 v3（2026-09-01）口径。** [论文](https://arxiv.org/abs/2605.05726)、[仓库](https://github.com/ThakiCloud/SKILLRET)、[数据集](https://huggingface.co/datasets/ThakiCloud/SKILLRET)。

最新论文报告 16,129 个技能、63,259 条训练查询和 4,392 条评测查询，并分离训练与测试技能池；公开专用检索模型。数据卡总目录为 17,810 个技能，其中还包含训练／测试划分外条目，因此不同数字不能混为同一统计口径。复现前应固定 revision 并实际清点。

**启发：**它适合验证“专项训练未见能力”，比随机切分同一批技能的查询更贴近你的目标。但查询由合成流程构造，不能直接称为真实用户行为或已验证执行成功记录；也要排查来源重复、描述近重复与教师措辞偏差。

### 4.5 MagicSelector：检索、排序、困难负例已经被进一步组合

**状态：2026 年 7 月预印本，最新摘要为 v2。** [论文](https://arxiv.org/abs/2607.17751)。

该工作结合任务分解、逐级排序、自蒸馏困难负例及动态 Top-K，作者报告跨工具基准的改进。它是一套多组件流程，不能当作单个轻量分类模型的同等预算对照。本次未核实到可下载的官方代码／权重。[方法版本 v1](https://arxiv.org/html/2607.17751v1)。

**启发：**困难负例、pointwise 到 listwise 的训练和分解增强，都需要检索既有方法后再定义新增部分。比较时同时报告总模型数量、调用次数、输入 token 与端到端开销。

### 4.6 较早先例：ToolRerank

**发表状态：LREC-COLING 2024。** 它针对训练见过／未见的工具做自适应截断与层次化排序，并在 ToolBench 场景中验证。[论文](https://aclanthology.org/2024.lrec-main.1413/)。

这说明“工具排序需要考虑未见工具”并非新命题。你的方法应说明比已有适配或排序策略多解决了什么，而不是只把任务名称换成 Agent 或 Skill。

## 5. 蒸馏与评测：会直接影响论文是否站得住

### 5.1 Distilling Step-by-Step：推理过程可用于训练，而非必须用于推理

**发表状态：Findings of ACL 2023。** [论文](https://aclanthology.org/2023.findings-acl.507/)、[代码](https://github.com/google-research/distilling-step-by-step)。

作者让教师产生标签与理由，再用多任务方式训练小模型。标签预测和理由预测可采用不同任务前缀，因此推理时可以走标签分支，不必先输出完整理由。论文展示小模型在特定任务与数据条件下超过大模型 few-shot 基线，不是证明一般性取代大模型。仓库已归档，复用时应适配依赖。

**启发：**可以检验“训练时学习判断依据，推理时只给分数”。但“加入 CoT 蒸馏”本身已有先例。你的新贡献可能涉及更适合未见能力的教师信号、反事实比较或训练目标，必须与普通标签 SFT、理由辅助训练公平对比。

### 5.2 ToolEX／ToolEQ：单一正确工具标签可能误判能力

**状态：2026-09-08 预印本。** *Tool Retrievers Are Underestimated: Annotation Expansion Reveals True Capability*。[论文](https://arxiv.org/abs/2609.08327)。

作者扩展功能等价的工具答案，指出原始标注遗漏可行工具会影响排名，并可能夸大部分微调收益。这是其研究设置中的发现，不能推广成“工具检索微调普遍无效”。

**启发：**负例不只是“原标注中没有出现”。你需要审查困难负例是否真不适合，并在少量人工核验集上标注可接受集合。否则模型可能只是学会复现某个教师的偏好，而没有更好地理解能力。

### 5.3 与本研究暂时分开的方向

[Switchcraft](https://arxiv.org/abs/2605.07112)用小型路由器在多种 LLM 中选择执行工具调用的模型，研究成本和调用正确率。它可用于未来扩展，但选择执行模型与选择哪个工具是不同任务。本轮不把成本路由、完整多步规划、参数生成一起纳入主问题。

## 6. Jev 类公开项目：能借鉴什么，不能据此证明什么

| 项目 | 本次看到的实现与进度 | 对你的用途与限制 |
|---|---|---|
| [zhihz/OpenJEV](https://github.com/zhihz/OpenJEV) | 冻结 Qwen3-4B-Instruct-2507，读取答案标签概率，提供语义判断接口；研究预览 | 适合原始小模型直接评分基线；不是已训练出新判别模型的证据 |
| [TheoLeeCJ/SemIf](https://github.com/TheoLeeCJ/SemIf) | Jev 风格语义接口与共享前缀等推理实验；提供 [MLX](https://github.com/TheoLeeCJ/SemIf/blob/master/docs/MLX.md) 与[复现说明](https://github.com/TheoLeeCJ/SemIf/blob/master/docs/REPRODUCE.md) | 借鉴多问题共享输入、接口与测量方法；性能须在你的硬件上重测 |
| [ekzhang/openjev-sglang](https://github.com/ekzhang/openjev-sglang) | 借助 SGLang 的 prefill、首 token 评分及缓存复用组织调用 | 借鉴服务优化；不能把缓存命中下的收益当作训练质量提升 |
| [xingwudao/OpenJev](https://github.com/xingwudao/OpenJev) | SDK／本地服务原型，真实推理仍列为后续工作 | 主要参考接口设计，不适合作为模型能力证据 |

这些同名或近似命名仓库不是同一个项目，也不等于 Jev 官方模型的完整复现。当前公开证据不足以由它们反推出 Jev 的全部结构、训练数据、损失函数或所谓 RLCD 的具体实现。因此，原报告中对闭源内部机制的推断，应继续标为假设。

## 7. 已有成果达到哪里，尚不能推出什么

| 已有证据支持的判断 | 尚不能直接推出的结论 |
|---|---|
| 小模型可以接受动态标签，执行多种分类任务 | 能理解任意新能力，或达到大模型的全部推理能力 |
| 语言模型能直接提供候选分数，避免长答案解码 | 一次前向在任意长目录下都低延迟 |
| 专项工具／技能训练已有有效结果和公开模型 | 对中文、业务 Agent、长上下文同样有效 |
| 较完整描述、困难负例和排序训练可能改善检索 | 改进一定来自模型算法而非额外信息或标注偏差 |
| 已有大规模候选目录实验 | 人工评测查询充分，或已证明生产稳定性 |
| 部分模型开放权重与推理代码 | 原训练语料、清洗、教师调用和训练配方全部可复现 |

尤其不能把不同论文的 F1、Hit@1、NDCG 和执行成功率放在一张数值表中直接排名。硬件、候选来源、输入长度和批量不同，速度同样不可直接横比。

## 8. 对你当前研究方案的调整建议

### 8.1 保留目标，收紧创新表述

仍建议使用工作题目：**面向智能体路由的轻量语义决策模型训练方法研究**。

暂时不要使用“首次实现动态标签路由”“首次让 LLM 直接做分类”“首个 4B 工具路由模型”等说法。新增业务数据、中文适配或接入 Intent Hub 可以成为实验／工程贡献，但不自动构成新的算法方法。

新颖性应最终写成：已有方法在条件 X 下暴露问题 Y；本研究提出方法 Z；在控制数据、输入信息与计算预算后，Z 稳定改善 Y，且没有不可接受的其他损失。

### 8.2 三条可探索主线，先用小实验筛选

下面都是本报告提出的研究假设，尚非确认创新点；建议先选一个作为主线，其余作为对照或消融。

| 候选主线 | 具体问题 | 必须比较的先例 | 值得继续的证据 |
|---|---|---|---|
| A. 面向未见能力的判断知识蒸馏 | 怎样把教师对条件、否定与职责差异的理解迁移给直接评分的小模型？ | 标签 SFT、Distilling Step-by-Step、Qwen3-Reranker／ToolRank | 同训练规模下，未见能力和复杂语义切片稳定提升，推理不依赖长 CoT |
| B. 候选比较与抗干扰训练 | 候选之间应互相比较多少？相近、等价或无关候选怎样影响判断？ | UniMC 的干扰控制、GLiClass／Jina／SCX 的联合评分 | 不只提高固定候选集正确率，还能抵抗顺序、数量和干扰变化 |
| C. 有限描述预算下的能力理解 | 在接入只提供描述时，保留哪些信息才能接近完整文档判断？ | Tool-REX 的描述扩展、SkillRouter 的全文与元数据对比 | 在相同描述 token 预算下优于普通摘要，且新增能力无需更新参数 |

**当前建议优先验证 A，B 作为结构或训练消融，C 作为输入信息控制。** 理由是 A 最贴近你“训练出具有 LLM 理解能力的强分类模型”的初衷；它也可能失败。如果现成 reranker 已解决这些问题，就应缩小或更换主线，而非强行包装普通微调。

对 B 的特别提醒：UniMC 限制选项干扰，GLiClass 等利用候选交互，两者提供了可检验的设计差异；这不等于文献存在逻辑冲突，任务和训练设置可能不同。

### 8.3 第一轮实验应回答什么

**实验一：现成模型已经有多强？**

固定请求、候选及描述，比较以下最小基线组；先跑通少量样本与质量测量，再扩大规模。

| 基线 | 目的 |
|---|---|
| Intent Hub 现有召回路径 | 建立实际系统参照；运行时配置与实现另行核实 |
| Qwen3-4B-Instruct：生成候选 ID／直接标签评分 | 同基模区分输出形式的影响 |
| Qwen3-Reranker-0.6B 与 4B | 区分专项评分训练和规模影响 |
| 合适语言版本的 GLiClass | 检验更小的判别模型是否足够 |
| ToolRank-4B 或 SkillRouter 排序器 | 与已训练的领域模型比较 |

SCX Router、Jina listwise 可作为第二批结构对照，不必第一轮全部部署。模型输出统一为候选分数或可映射的选择结果，但保留各自推荐输入格式，记录适配方式。

**实验二：错误来自信息缺失，还是模型不会判断？**

对同一请求比较原短描述、完整文档和固定预算摘要；额外标记条件、否定、上下文、职责相近、多个可接受候选。使用一小批人工审查样本检查标签与错误机制。不要仅由同一个教师生成训练标签并充当唯一评委。

**实验三：最简单的训练是否已经足够？**

固定基模与训练划分，对比无专项训练、普通标签 SFT、理由辅助训练及拟议方法。匹配样本量之外，还报告教师 token／调用成本、学生训练 token 与 GPU 时长，避免把更多预算误认为更优目标函数。

关键消融可采用“删除理由”“删除反事实／困难候选”“换随机负例”“冻结或取消候选交互”。只保留与所选主线有关的消融，不要求全部做。

### 8.4 数据与评价的最低要求

1. **按能力及来源划分。** 优先利用 SkillRet 的能力隔离设计；检查近重复描述、同源仓库与合成模板，不能只随机切分查询。这里的“未见”只指专项训练未见，不保证基模预训练未见。
2. **公共协议与改造协议分开。** ToolRet／SkillRet 原指标保留；如果抽取小候选集做决策，单列结果。召回率、候选内选择与端到端效果分开。
3. **保留多正确答案。** 人工抽查等价能力和困难负例。联合工具任务单列，不能强行转成单标签。
4. **质量之外量实际开销。** 在同一硬件与相同输入分布上报告 p50／p95 延迟、吞吐、峰值显存、输入 token、候选数和缓存条件；区分模型前向与端到端链路。
5. **用重复运行或区间表达不确定性。** 小人工集尤其需要谨慎。对于共享技能来源的数据，可按技能或来源分组评估区间，避免假设所有请求相互独立。
6. **无合适候选与信息不足保留为诊断项。** 可评价错误接受、拒绝与覆盖，但不因它们重要就提前把论文改成拒绝路由研究。

### 8.5 继续与转向的判断

- 若普通 SFT 已达到预期，复杂蒸馏没有稳定增益：保留简单模型，重新寻找问题，不把复杂化本身当贡献。
- 若收益只出现在训练见过的能力：优先解决划分、数据覆盖或过拟合；不能声称即插即用。
- 若完整文档有效而短描述无效：先研究信息表示与压缩，增加模型参数未必解决问题。
- 若 0.6B 已在质量—资源曲线上占优：无需为了“LLM 能力”坚持 4B。
- 若检索经常漏掉正确能力：先单独量召回上限；候选内分类器不能补回完全未输入的信息。
- 若新方法只胜过原始 instruct，却不及现成领域模型：它仍是有效实验，但不足以支撑“优于现有方法”的主张。

## 9. 推荐阅读与复现顺序

不按发表时间逐篇堆积，按研究决策阅读：

| 顺序 | 阅读对象 | 读完应产出的判断 |
|---|---|---|
| 1 | GLiClass＋Qwen3-Reranker | 动态标签与直接评分分别如何实现；选定第一批基线 |
| 2 | SCX Router＋Jina reranker | 解码器、候选交互和缓存如何结合；哪些结构已有先例 |

每篇记录任务、输入、输出、训练信号、未见划分、强基线、关键消融、公开资产和失败边界。首轮最有价值的产出，是一张同协议模型对照表和一份经人工核验的错误分类，而不是立即确定论文算法名称。
